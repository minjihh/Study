## 2. 🔍 코드에서 찾은 함정 포인트 (오늘의 핵심)

### 2-1. RNN 파라미터 — 주석과 코드가 다를 때 (`keras/keras54_RNN2_summary.py`)
- 코드: `SimpleRNN(10, input_shape=(3,1))` → `Dense(7)` → `Dense(1)`.
- 그런데 아래 붙여 둔 summary는 `SimpleRNN (None, 5) 35` — **units=5일 때 결과**입니다.
- 공식: `units × (feature + units + 1)` → units=10이면 `10×(1+10+1) = 120`, Dense(7) = `10×7+7 = 77`, Dense(1) = `8` → **총 205**.
- 교훈: 복사해 온 summary 주석은 **실제 코드와 다를 수 있으니** 공식으로 직접 검산하는 습관.

### 2-2. split_x가 실제로 만드는 것 (`keras/keras56_split2.py`)
- `a` = `(10,2)` (1열: 1~10, 2열: 9~0). `size=5`인데 함수 안에서 `subset[:-1]`을 append → 창마다 **4행만** 저장 → `bbb.shape = (6,4,2)`.
- `x = bbb[:, :-1, :]` → `(6,3,2)`, `y = bbb[:, -1, 1]` → 4번째 행의 **2열** → `y = [6,5,4,3,2,1]`.
- 즉 "연속 3행을 보고 다음 행의 2열 값 맞히기". 각 창의 5번째 행은 **버려짐**(size를 4로 줘도 같은 결과).
- 예측 입력 `[[8,2],[9,1],[10,0]]`의 '정답 패턴'은 **−1**인데, 학습 y는 1~6 범위뿐 → 출력이 1.19, 1.70처럼 나오는 건 **학습 범위 밖 외삽**에 약하기 때문.

### 2-3. padding / stride / pooling shape (`keras/keras38_padding_stride_0.py`)
- `Conv2D(10,(2,2), padding='same')` on `(10,10,1)` → **(10,10,10)**, 파라미터 `10×(2·2·1+1) = 50`.
- `MaxPooling2D()` (기본 pool 2, stride 2) → **(5,5,10)**.
- `Conv2D(9,(3,3), padding='valid')` → **(3,3,9)**, 파라미터 `9×(3·3·10+1) = 819`.
- 코드 주석 `# 8, 8, 9`는 MaxPooling이 **없다고 가정한** 값이라 실제와 다름.

### 2-4. Tokenizer 인덱스와 Embedding `input_dim` (`keras2/keras61_Embedding04_중요.py`)
- `word_index`는 **1부터** 시작(0은 패딩용 예약). 단어 30개 → 인덱스 1~30.
- 코드의 `Embedding(30, 100)`은 인덱스 0~29만 담을 수 있음 → 인덱스 **30**(`'구라친다'`)이 들어오면 CPU에선 `InvalidArgumentError`, GPU에선 조용히 0벡터 처리될 수 있음. 정석은 **`input_dim = len(word_index) + 1 = 31`**.
- 파일 상단에 `exit()`이 있어 모델 부분은 지금 실행되지 않음(그래서 에러를 못 봤을 수 있음).
- `pad_sequences(padding='pre', maxlen=5, truncating='post')`: 가장 긴 문장이 5단어라 잘리는 문장은 없음. `[28,29,30]` → `[0,0,28,29,30]`.
- `keras62_1_reuters`의 `Embedding(1000, 500, mask_zero=True)`: 패딩값 0을 이후 RNN 계층이 **무시**하도록 마스킹.

### 2-5. 다중 입력 앙상블 (`keras2/keras69_ensemble2.py`)
- 입력 3개: x1 `(100,2)`, x2 `(100,3)`, x3 `(100,4)` → 각 branch 출력 5, 3, 3 → `Concatenate` → **(None, 11)** → `mg2 Dense(10)` 파라미터 `11×10+10 = 120`.
- `train_test_split(x1, x2, x3, y, train_size=0.7)`처럼 **배열 여러 개를 한 번에** 나누면 같은 인덱스로 함께 섞임(행 대응 유지). 반환 순서: `x1_tr, x1_te, x2_tr, x2_te, x3_tr, x3_te, y_tr, y_te`.
- y = `3001 + i` 이고 예측 입력 x1 = `[100~105, 400~405]` → 이상적인 정답은 **3101~3106**(역시 학습 범위 0~99 밖 외삽).
- `Concatenate`(클래스, `Concatenate()([a,b])`) vs `concatenate`(함수, `concatenate([a,b])`) — 둘 다 같은 결과.

### 2-6. 동결의 두 얼굴 (`keras71_trainable_weights2.py`, `keras74_3_layers_부분동결.py`)
- keras71_2: **compile 전에** `model.trainable = False` → `fit`을 300 epoch 해도 가중치 **변화 없음** → loss가 매 epoch 똑같고, predict는 **초기 랜덤 가중치** 결과. (seed 333 고정이라 실행마다 같은 값)
- keras74_3: `model.layers` = `[vgg16, flatten, dense(100), dense(90), dense(80), dense(70), dense(10)]` → `model.layers[5]` = **Dense(70)** 동결.
  - 32×32 입력이면 VGG16 출력 `(1,1,512)` → Flatten 512.
  - Trainable: Dense100 `51,300` + Dense90 `9,090` + Dense80 `7,280` + Dense10 `710` = **68,380**
  - Non-trainable: VGG16 `14,714,688` + Dense70 `5,670` = **14,720,358**
- 주의: `trainable` 변경은 **compile 전에** 해야 확실히 반영됨(바꾼 뒤엔 다시 compile).

### 2-7. for문 튜닝의 함정 (`ml/m07_for로파라미터튜닝.py`)
- lr 5개 × max_depth 5개 = **25번** 학습, 각 조합을 **test 점수**로 비교해 best 선택.
- 문제: 하이퍼파라미터를 test로 골랐으니 그 test 점수는 **낙관적으로 편향**(test가 사실상 검증셋이 됨). → 그래서 m08부터 **train 내부 CV(GridSearchCV)** 로 고르고 test는 마지막에 한 번만.
- `best_parameters = lr, md` → **튜플** `(lr, md)` 저장.

### 2-8. 모듈의 전역변수 (`python_pkg/p31~p33`)
- 함수는 **자기가 정의된 모듈의 전역변수**를 봄. `p31_sample.test()`는 어디서 호출하든 `x : 111`.

# ✅ 정답 및 해설

**A1.** SimpleRNN `10×(1+10+1) = 120`, Dense(7) `10×7+7 = 77`, Dense(1) `7+1 = 8` → **총 205**. 붙어 있는 summary는 `SimpleRNN(5)`일 때(`5×(1+5+1)=35`, `5×7+7=42`) 결과를 그대로 복사해 둔 것.

**A2.** LSTM = 게이트 4개 → `4 × 10×(1+10+1) = 480`. GRU는 약 **3배**(TF2 기본 `reset_after=True`라 bias가 2세트 → `3×10×(1+10+2) = 390`).

**A3.** `bbb (6,4,2)`, `x (6,3,2)`, `y (6,)` = **[6, 5, 4, 3, 2, 1]** (각 창의 4번째 행 `a[i+3]`의 2열 = `9−(i+3)`).

**A4.** `size=4` → 창 7개, `subset[:-1]`로 3행씩 → `bbb (7,3,2)`, `x (7,2,2)`, `y (7,)`. 원래는 3행 보고 다음 1행을 맞혔는데, 이제는 **2행 보고** 다음 행을 맞힘(입력 길이 감소, 샘플 1개 증가). → 그래서 `predict` 입력 shape(1,3,2)도 (1,2,2)로 바꿔야 함.

**A5.** 2열은 1씩 감소하므로 다음 값은 **−1**. 학습 y가 1~6 범위에만 있어서 모델이 그 밖의 값(0, −1)을 잘 만들지 못함(외삽 불가). ReLU Dense층도 음수 출력 방향의 표현을 어렵게 만드는 데 한몫.

**A6.** (10,10,10) / 50 → (5,5,10) / 0 → (3,3,9) / `9×(3·3·10+1) = 819`. `MaxPooling2D`를 빼면 (10,10,10) → 3×3 valid → **(8,8,9)**.

**A7.** `(10−2)/2 + 1 = 5` → **(5,5,10)** (파라미터 50, stride는 파라미터 수와 무관).

**A8.** 5+3+3 = **(None, 11)**, mg2 = `11×10+10 = 120`.

**A9.** **8개**: `x1_train, x1_test, x2_train, x2_test, x3_train, x3_test, y_train, y_test` (배열마다 train, test 순서로 짝지어 반환, 같은 인덱스로 섞임).

**A10.** 가중치가 갱신되지 않으므로 **loss가 300 epoch 내내 같은 값**. `predict`는 seed(333)로 정해진 **초기 랜덤 가중치**의 출력 → 1~5와 무관한 값.

**A12.** **compile을 (다시) 해야** 학습 시 반영됨. 바꾼 후 `model.summary()`로 Trainable/Non-trainable params 확인 권장.

**B1.** 인덱스는 1~30이라 `input_dim`이 최소 31이어야 함. `Embedding(30,…)`은 0~29만 조회 가능 → 30이 들어오면 CPU에서 `InvalidArgumentError (indices[...] = 30 is not in [0, 30))`. 올바른 값: `len(token.word_index) + 1 = 31`. 현재는 패딩 출력 후 `exit()`이 있어 모델 코드가 실행되지 않음.

**B2.** maxlen=5: `[0,0,28,29,30]`, `[10,11,12,13,14]`(그대로). maxlen=3: `[28,29,30]`(그대로), `truncating='post'` → **뒤를 잘라** `[10,11,12]`.

**B3.** Embedding `31×100 = 3,100` (출력 (None,5,100)), SimpleRNN `10×(100+10+1) = 1,110`, Dense `10+1 = 11` → 총 **4,221**. (Embedding 파라미터는 입력 길이와 무관)

**B4.** 값 0을 패딩으로 보고 **마스크**를 만들어, 이후 RNN/LSTM이 해당 timestep을 계산에서 건너뛰게 함 → 앞에 0이 많이 붙은 짧은 문장도 왜곡 없이 처리. (그래서 0을 실제 단어 인덱스로 쓰면 안 됨)

**B5.** Embedding의 첫 인자 `input_dim` = **단어 사전 크기(입력 쪽)**, Dense의 첫 인자 `units` = **출력 노드 수**.

**E2.** 신경망은 학습한 입력·출력 범위 안에서 함수를 근사할 뿐, 범위 밖으로 추세를 이어가는 구조가 아님(특히 ReLU 조합은 범위 밖에서 단순 선형으로 꺾이거나 0에 막힘). 해결: 입력/출력 스케일링, **절대값 대신 변화량(차분)이나 비율을 예측**, 학습 데이터 범위 확장, 시계열이면 정규화 후 역변환.

**E4.** 예) keras에서 신경망 학습(데이터 → 모델 → 손실 최소화)과 shape 감각을 익히고, ml에서 교차검증·하이퍼파라미터 탐색으로 "모델을 공정하게 고르는 법"을 배움. RAG에서는 학습 대신 **임베딩(Embedding 층과 같은 벡터화 개념)** 과 벡터 검색으로 LLM에 외부 지식을 붙이고, LangGraph에서 이 검색·LLM·도구를 노드로 엮어 **여러 단계/병렬 에이전트 워크플로**를 만듦.
