## 0. 최근 추가분 집중 정리 (11-04, 11-06 커밋)

### 0-1. K-Fold / 교차검증 (`ml/m02`, `ml/m03`)
- `KFold(n_splits=5, shuffle=True, random_state=333)`: 데이터를 5조각으로 나눠 돌아가며 1조각을 검증용으로 사용.
- `cross_val_score(model, x, y, cv=kfold)`: **fit까지 알아서 해주고** fold별 점수 배열을 반환. 분류는 acc, 회귀는 R².
- **m02**: 전체 데이터(x, y)에 바로 K-Fold 적용.
- **m03**: `train_test_split` **먼저** → train 데이터에만 K-Fold 적용 → test는 마지막 평가용으로 보관. 이게 정석.
- 스케일링은 `fit_transform(x_train)` / `transform(x_test)` — **test에는 fit 금지**.
- `StratifiedKFold`: 분류에서 fold마다 클래스 비율을 유지 (회귀에서는 사용 불가).
- `cross_val_predict`: 각 fold의 검증 구간 예측값을 모아서 반환.

### 0-2. 모든 모델 돌려보기 (`ml/m04`, `ml/m05`)
- `all_estimators(type_filter='classifier' | 'regressor')` → `(이름, 클래스)` 튜플 리스트 반환 (sklearn 1.9.1 기준 회귀 44개).
- `for name, model in all:` → `model()`로 **인스턴스 생성** → fit → score. 필수 인자가 필요한 모델은 생성 단계에서 에러라 `try/except` 안에서 생성해야 함.
- m05는 같은 흐름에 K-Fold 교차검증을 결합.

### 0-3. 하이퍼파라미터 튜닝 (`ml/m07`, `ml/m08`)
- **m07**: `for` 이중 반복문으로 `learning_rate × max_depth` 조합(5×5=25)을 직접 돌려 best score/params 기록.
- **m08**: `GridSearchCV(model, parameters, cv=kfold, n_jobs=-1)`로 자동화.
  - `parameters`가 리스트 안의 딕셔너리 3개이면, 각 딕셔너리 안에서 **곱**, 딕셔너리끼리는 **합**: 예) 2×3×3 + 4×3 + 4×3 = 18+12+12 = 42 조합 (×5 fold = 210번 학습).
  - `best_estimator_`, `best_params_`, `best_score_`(CV 평균, train 쪽 점수라 낙관적), `model.score`(test 점수).
  - `n_jobs=-1`: 모든 CPU 코어 사용.

### 0-4. Feature Importance (`ml/m01`)
- 트리 계열 `feature_importances_`; XGBoost의 `get_booster().get_score(importance_type='gain')`.
- **Gain**: 해당 feature로 분기했을 때 손실 개선량(실질 기여도). 기본값(빈도, weight)과 다름.

## 2. Keras 기초 ~ 중급 (`keras/`)
### 2-1. 기본기 (keras01~19)
- 흐름: **1.데이터 → 2.모델구성 → 3.컴파일/훈련 → 4.평가/예측**.
- `Sequential` + `Dense`, `compile(loss, optimizer)`, `fit(epochs, batch_size)`.
- `train_test_split`, `validation_split`/`validation_data`, `r2_score`, 과적합(overfit) 확인은 `hist.history`의 loss vs val_loss.
- 데이터셋: california, diabetes, boston, dacon_ddarung, kaggle_bike (회귀) / cancer, santander (이진분류) / iris, wine, covtype, digits (다중분류).

### 2-2. 콜백 / 분류 설정 (keras20~24)
- `EarlyStopping(monitor='val_loss', mode='min', patience=N, restore_best_weights=True)` — 클래스는 CamelCase, 인스턴스는 `es`로 만들어 `callbacks=[es]`.
- 이진분류: 출력 `Dense(1, activation='sigmoid')`, loss `binary_crossentropy`, metrics `acc`.
- 다중분류: 출력 `Dense(클래스수, activation='softmax')`, loss `categorical_crossentropy`(One-Hot 필요) 또는 `sparse_categorical_crossentropy`(One-Hot 불필요).
- 회귀: 출력 활성화 없음(linear), loss `mse`.

### 2-3. 전처리/저장 (keras25~32)
- `model.summary()`, `input_shape` vs `input_dim`.
- Scaler: MinMax, Standard, MaxAbs, Robust. **train에만 fit, test는 transform**.
- 모델 저장/불러오기: `model.save()` / `load_model()` (모델+가중치), `save_weights()` / `load_weights()` (가중치만 — 모델 구조를 먼저 똑같이 만들고 compile 후 로드).
- `ModelCheckpoint(save_best_only=True)`: 가장 좋은 시점의 모델 저장.

### 2-4. 규제 / 함수형 / GPU (keras33~35)
- `Dropout(rate)`: 학습 시 일부 노드를 꺼서 과적합 방지, **파라미터 0개**, 평가/예측 시에는 자동 비활성화.
- 함수형 모델: `Input` → `Dense(...)(이전층)` → `Model(inputs, outputs)`. 다중 입력/출력, 분기·병합 가능.
- GPU 확인: `tf.config.list_physical_devices('GPU')`.

### 2-5. CNN (keras36~43)
- `Conv2D(filters, kernel_size, input_shape=(H,W,C))` — 입력은 **4차원** `(N,H,W,C)` (mnist는 `reshape(-1,28,28,1)`).
- 출력 크기: `(입력 − 커널 + 2·패딩)/stride + 1`; `padding='same'`이면 크기 유지.
- 파라미터 수 = `필터수 × (커널가로 × 커널세로 × 입력채널 + 1)`.
- `MaxPooling2D`: 영역 최댓값으로 축소(파라미터 0). `GlobalAveragePooling2D`: Flatten 대체, 파라미터/속도 이점.
- 데이터: mnist, fashion_mnist, cifar10, cifar100. 이미지 스케일링은 `/255.`.
- DNN(Flatten) vs CNN 비교(keras41), 정형 데이터를 CNN으로 푸는 실험(keras42).

### 2-6. 이미지 증강 / 데이터 저장 (keras44~51)
- `ImageDataGenerator`: `rescale`, `horizontal_flip`, `rotation_range`, `width_shift_range` 등 → `flow_from_directory`, `flow`.
- 이미지를 `np.save`로 `.npy`로 저장 후 로드하면 매번 이미지 읽는 시간 절약.
- `img_to_array`, 증강 데이터를 원본에 이어 붙여 학습(augment).

### 2-7. 최적화 / 학습률 (keras52~53)
- 옵티마이저: Adam, SGD, RMSprop 등과 `learning_rate`에 따른 성능 비교.
- `ReduceLROnPlateau(factor, patience)`: val_loss가 개선 안 되면 lr을 감소시킴.

### 2-8. RNN 계열 (keras54~59)
- 입력은 **3차원** `(samples, timesteps, features)`. `split_data`(keras56)로 시계열을 윈도우로 자름.
- `SimpleRNN`, `LSTM`, `GRU`; `return_sequences=True`면 3차원 출력(RNN 층을 쌓을 때 필요).
- `Bidirectional(...)`: 정방향 + 역방향. jena(기온 예측) 데이터 실습.

## 3. Keras 2 — 자연어 / 고급 (`keras2/`)
- **Tokenizer** (keras60): `fit_on_texts` → `word_index`(빈도 높은 순 번호, 동률이면 먼저 나온 순) → `texts_to_sequences`. 번호는 크기 의미가 없으므로 One-Hot 또는 Embedding 필요.
- **pad_sequences**: `padding='pre|post'`, `maxlen`, `truncating`.
- **Embedding** (keras61): `Embedding(input_dim=단어수+1, output_dim, input_length)`. One-Hot 대비 차원이 작고 학습 가능.
- 데이터셋: reuters(다중분류), imdb(이진분류).
- **sparse_categorical_crossentropy** (keras63): y를 One-Hot 안 해도 되며 성능 차이는 거의 없음.
- **Reshape 층** (keras65), **Conv1D** (keras67/68): 시계열·정형 데이터에 합성곱. 3차원 입출력이라 `Flatten`/`GAP` 필요.
- **앙상블** (keras69): 입력이 여러 개인 모델 → `Concatenate`로 병합 → Dense. (소문자 `concatenate`는 함수, 대문자 `Concatenate`는 클래스)
- keras70: 상관계수(correlation), 예측, 주가 맞추기 실습.
- **전이학습** (keras71~76): 
  - `model.trainable = False` → `weights` 개수는 유지, `trainable_weights`는 0.
  - `VGG16(weights='imagenet', include_top=False, input_shape=(32,32,3))`: `include_top=False`면 FC층 제거, 입력 크기 변경 가능.
  - 레이어별 동결: `model.layers[5].trainable = False`.
  - 여러 Application 모델(ResNet, DenseNet, MobileNet, EfficientNet, Xception 등)의 가중치 수 비교.

## 5. RAG (`RAG/`, `RAG.txt`, `VectorDB.txt`)
- **RAG** = Retrieval(검색) + Augmented(질문에 자료를 붙여 보강) + Generation(근거 기반 생성).
- 환경설정: `.env` + `python-dotenv`의 `load_dotenv()`, `os.environ["KEY"].strip()`, OpenAI 호환 API는 `base_url`도 지정.
- **LCEL**: `chain = prompt | model | output_parser`; `chain.invoke({...})`.
- 파이프라인: **로드(TextLoader, PyPDFLoader) → 청킹(RecursiveCharacterTextSplitter: chunk_size, chunk_overlap) → 임베딩(OpenAIEmbeddings `text-embedding-3-small`=1536차원, `-large`=3072차원) → 벡터DB 저장 → 검색 → LLM 답변**.
- **Chroma**: 문서 원문+메타데이터+임베딩 관리, `persist_directory`, `collection_name`. 같은 코드를 반복 실행하면 sqlite에 문서가 계속 **누적**됨.
- **FAISS**: 벡터 검색에 특화, `IndexFlatL2`(유클리드 거리), `InMemoryDocstore` 필요, `save_local`/`load_local`. 대용량에서 빠름.
- 다른 임베딩 모델: `bge-m3`, `Qwen3-Embedding-0.6B`(HuggingFace, 로컬).
- Gradio로 챗봇 UI(history, 유사도 확인, 프롬프트 조정).
- **검색 방식**: BM25(키워드 기반) vs 벡터(의미 기반) vs **하이브리드(앙상블)** — 둘을 가중 결합.

## 6. LangGraph (`LG/`)
- `TypedDict`: 타입 힌트용(강제성 없음). `State`를 정의하는 데 사용.
- `Annotated[list, add_messages]`: **리듀서** — 메시지를 덮어쓰지 않고 누적.
- 그래프 5단계: **State 정의 → 노드(함수) 정의 → `StateGraph` 구성/`add_node` → `add_edge(START→…→END)` → `compile()` → `invoke()`**.
- 노드는 State 일부를 담은 dict를 반환 → State에 병합.
- **Tool calling**: `TavilySearch` 등의 도구 → `llm.bind_tools(tools)` → `ToolNode(tools)` + `tools_condition`(조건부 엣지: 도구 호출 필요하면 tools, 아니면 END) → 도구 실행 후 다시 chatbot으로.
- **Memory** (lg08): checkpointer(`MemorySaver`) + `thread_id`로 대화 기억.
- **병렬 실행/병합** (lg09): START에서 두 노드로 엣지를 걸면 동시에 실행, 두 노드에서 `merge`로 엣지를 걸면 둘 다 끝난 뒤 병합. 여러 노드가 같은 키에 쓰면 리듀서 필요(→ `_concat`).
- 시각화: `graph.get_graph().draw_mermaid_png()`.

# ✅ 정답 및 해설

**A1.** 따로 fit 불필요. `cross_val_score`가 fold마다 fit/평가를 수행. 반환값은 fold별 점수 배열(분류=acc, 회귀=R²), 보통 `np.mean`으로 평균을 봄.

**A2.** m02는 전체 데이터에 K-Fold, m03은 `train_test_split` 후 **train에만** K-Fold. m03은 test를 한 번도 안 건드려서 최종 일반화 성능을 공정하게 측정 가능.

**A3.** `cross_val_predict(model, x_test, y_test)`는 **test 데이터로 다시 학습**(fold별 fit)한 뒤 test를 예측함 → train에서 학습한 모델의 예측이 아님, 데이터 누수/개념 오류. 올바른 방법은 `model.fit(x_train, y_train)` 후 `model.predict(x_test)`.

**A4.** 각 fold의 클래스 비율을 전체와 유사하게 유지. 회귀는 연속값 타깃이라 "클래스"가 없어 비율 유지 개념이 성립하지 않음.

**A5.** 조합 18 + 12 + 12 = **42**, ×5 fold = **210번** (+ refit 1번 = 211번).

**A6.** `best_score_`는 train 내부 CV 검증 평균(튜닝으로 선택된 최고값이라 낙관적 → 과적합 가능), `model.score`는 한 번도 안 본 test 점수. 일반적으로 `best_score_`가 더 높게 나오는 경향.

**A7.** 장점: 코드로 흐름·로직 제어 자유. 단점: CV가 없어 test로 직접 선택(= test 정보 누수), 병렬화/자동화 부족. GridSearchCV는 CV·병렬(`n_jobs`)·refit 자동.

**A8.** 일부 estimator는 필수 인자가 있거나 데이터 형태가 안 맞아 **생성/학습 시 예외**가 발생하기 때문. 전체 루프가 중단되지 않게 하려고.

**A9.** 기본(`feature_importances_`)은 중요도(XGBoost 기본은 weight/빈도 기반 개념으로 학습), gain은 해당 feature 분기로 인한 **손실 감소량 평균** → 실제 성능 기여도에 가까움.

**A10.** iris는 분류 데이터(타깃이 클래스). 회귀 모델을 평가하려면 california, diabetes 같은 회귀 데이터를 써야 의미 있는 R²가 나옴. (`stratify=y`도 회귀에는 부적절)

**B1.** import 시 모듈 파일의 최상위 코드가 모두 실행되는데, p01_car.py 끝에 `drive()` 호출이 있기 때문.

**B2.** 모듈을 import할 때는 실행되지 않고, 직접 실행(`python car.py`)할 때만 실행되도록 분리.

**B3.** `machine.car.drive()`. `from machine.car import drive`는 `drive()`로 바로 호출 (네임스페이스 접두어 생략).

**C1.** 이진: sigmoid + binary_crossentropy / 다중(One-Hot): softmax + categorical_crossentropy / 다중(정수): softmax + sparse_categorical_crossentropy / 회귀: 활성화 없음(linear) + mse.

**C2.** 훈련 종료 후 **val_loss가 가장 좋았던 시점의 가중치로 복원**. patience=10은 개선이 없어도 10 epoch까지는 더 기다림.

**C3.** test 정보가 스케일 기준에 섞여 누수가 발생. train에서 fit한 기준으로 test는 `transform`만.

**C4.** `save` → `load_model(path)` 만으로 복원 (구조+가중치+컴파일 정보). `save_weights` → 같은 구조의 모델을 먼저 정의/compile 한 뒤 `load_weights(path)`.

**C5.** 0개. 학습 시에만 일부 노드를 꺼서 규제하고, 평가/예측 시에는 비활성화(전체 노드 사용).

**C6.** 출력 (26,26,64), 파라미터 `64×(3×3×1+1)=640`. 다음 `Conv2D(32,(3,3))`: `32×(3×3×64+1)=18,464`.

**C7.** `(32−3)/2+1 = 15.5` → 내림하여 **15** (15×15).

**C8.** 파라미터 수 감소(과적합↓), 연산 속도↑, 입력 크기에 덜 민감 → 보통 성능도 좋아짐.

**C9.** DNN 2차원 `(N, features)`, RNN 3차원 `(N, timesteps, features)`, CNN 4차원 `(N, H, W, C)`.

**C10.** `return_sequences=True` (3차원 출력을 다음 RNN 층에 전달).

**C11.** val_loss 등이 `patience` 동안 개선되지 않을 때 **learning rate를 factor 배로 감소**시켜 더 세밀하게 수렴하도록 함.

**C12.** 매번 이미지 파일을 읽고 변환하는 시간을 줄이고, 증강 결과를 고정/재사용 가능(속도·재현성).

**D1.** 빈도 높은 순(동률이면 먼저 나온 순)으로 1부터. 번호는 순서/크기 의미가 없는데 모델이 수치 대소로 해석하므로 One-Hot 또는 Embedding으로 바꿔야 함.

**D2.** 길이 3 → 앞쪽에 0 두 개 채움(`[0,0,a,b,c]`). 길이 7 → `truncating='post'`이므로 **뒤에서** 잘라 앞 5개만 유지.

**D3.** `31 × 10 = 310`.

**D4.** y의 One-Hot 인코딩(`to_categorical`/`OneHotEncoder`)을 생략하고 정수 라벨 그대로 사용 가능.

**D5.** 리스트로: `model.fit([x1_train, x2_train], y_train, ...)`. 입력 순서는 `inputs=[...]`와 동일.

**D6.** `weights`: 6 (층 3개 × (kernel+bias)) 그대로, `trainable_weights`: 0.

**D7.** ① 상단 Flatten/FC 층 제거 ② input_shape를 원하는 크기(예: 32×32×3)로 변경 가능.

**D8.** `False`: 데이터가 적고 사전학습 특징을 그대로 쓰고 싶을 때(빠르고 안정적). `True`: 데이터가 충분하고 도메인이 달라 fine-tuning이 필요할 때.

**E1.** Retrieval(벡터DB에서 검색), Augmented(질문에 검색 자료를 붙여 보강), Generation(근거 기반 답변 생성).

**F2.** State 정의 → 노드 함수 정의 → `StateGraph(State)` 생성 → `add_node` → `add_edge`(START/END 포함) → `compile()` → `invoke()`.

**F3.** `ToolNode`: LLM이 요청한 도구를 실제로 실행하는 노드. `tools_condition`: 마지막 메시지에 tool call이 있으면 tools로, 없으면 END로 분기. 도구 실행 후 결과를 chatbot으로 되돌려 최종 답변 생성.
