### 0-1. Python: `map` / `lambda` (`python/p01_map.py`, `p02_lambda1~3.py`)
- `map(함수, 반복가능객체)` → 각 원소에 함수를 적용하는 **map 객체(지연 계산 이터레이터)** 반환. 그래서 `print(result)`는 `<map object at ...>`가 찍히고, `list(result)`로 바꿔야 `[10, 20, 30, 40]`이 보임.
  - 이터레이터라 **한 번 소비하면 끝**: `list(result)`를 두 번 하면 두 번째는 `[]`.
- `lambda 인자: 반환식` = 이름 없는 한 줄 함수. `aaa = lambda x, y: x + y` ≡ `def aaa(x, y): return x + y`.
- 조건 표현식과 조합: `list(map(lambda x: "합격" if x >= 60 else "불합격", score))` → `['합격','불합격','합격','불합격','합격']`.
- 11-12 활성화 함수(keras78)에서 `sigmoid = lambda x: ...`로 쓴 것과 같은 문법.

### 0-2. Softmax (`keras2/keras78_09_softmax.py`)
- `softmax = lambda x: np.exp(x) / np.sum(np.exp(x))`
- x = `[1,2,3,4]` → **`[0.032, 0.087, 0.237, 0.644]`**, 합 = 1 → "확률"처럼 해석 → 다중분류 출력층.
- `exp`를 쓰는 이유: ① 모든 값을 **양수**로 만들고 ② 큰 값은 더 크게, 작은 값은 더 작게(차이 확대). 1씩 차이 나는 입력이 출력에선 약 **e배(2.718배)** 씩 차이 남.
- ⚠️ 코드 보충
  - `plt.pie(ratio, labels, ...)`: `pie`의 **두 번째 위치 인자는 `explode`**(조각을 떼어내는 거리)입니다. 라벨을 붙이려면 `plt.pie(ratio, labels=labels, ...)`처럼 **키워드로** 넘겨야 합니다. 지금 코드는 y값만큼 조각이 바깥으로 떨어져 보이고 라벨은 안 나옵니다. (`plt.grid()`도 파이 차트에선 의미 없음)
  - 실무에선 overflow 방지를 위해 `np.exp(x - np.max(x))`로 계산(결과 동일).

### 0-3. 경사하강법 (`keras78_gradient1.py`, `keras78_gradient2.py`)
- 함수 `f(x) = x² − 4x + 6` → 최솟값은 **x=2, f(2)=2** (gradient1에서 빨간 점 `(2,2)`로 표시).
- 미분(기울기) `f'(x) = 2x − 4` → `gradient = lambda x: 2*x - 4`.
- 업데이트 규칙: **`x = x − learning_rate × gradient(x)`** (기울기의 반대 방향으로 이동).
- gradient2 설정: 초기값 `x = 100.0`, `learning_rate = 0.1`, `epochs = 50`
  - 정리하면 `x_new = 0.8·x + 0.4` → 최솟값(2)까지 남은 거리가 매 epoch **0.8배**로 줄어듦.
  - 1 epoch 후 x = 80.4 (f = 6148.56) → 50 epoch 후 x ≈ **2.0014**, f ≈ 2.000002.
- 학습률의 역할 (이 함수 기준, 거리 배율 = `|1 − 2·lr|`)
  - `lr = 0.1` → 0.8배씩 천천히 수렴, `lr = 0.5` → **한 번에** x=2 도착
  - `lr = 1.0` → 100 ↔ −96 무한 **진동**, `lr > 1` → **발산**, 너무 작으면(0.001) 매우 느림
- `x = np.linspace(-1, 6, 100)`: −1~6을 **끝점 포함 100등분**(arange와 달리 stop 포함). gradient2에선 이후 `x = 100.0`으로 덮어써져 사실상 미사용.
- `plt.plot(2, 2, 'sk', color='red')`: 포맷 문자열 `'sk'`(검은 사각형)와 `color='red'`가 겹침 → 경고 후 키워드 `color`가 적용되어 빨간 사각형.

### 0-4. 학습률 실험 (`keras2/keras79_lr.py`)
- x=10, y=10 → 정답 가중치 **w=1**. 시작 `w=0.001`, `lr=0.001`, `epochs=1000`.
- **미분을 쓰지 않는** 방식: `w+lr`과 `w−lr` 두 후보의 loss를 각각 계산 → loss가 작은 쪽으로 **lr만큼 이동**.
  - `if up_loss > down_loss: w -= lr  else: w += lr`
- 매 epoch 0.001씩 증가 → **i=999에서 Predict 10.0**, loss 0 도달 (1000 epoch가 딱 맞게 설정됨).
- `loss = (hypothesis - y)**2` → MSE 형태(샘플 1개, bias 없음).
- ⚠️ 코드 보충
  - `print(i, "Loss :", round(loss, 4)+100, ...)` → 출력되는 Loss는 실제 loss에 **+100이 더해진 값** (i=0: 실제 99.8001 → 출력 199.8001, 마지막: 100.0). 실제 loss를 보려면 `+100` 제거.
  - `for i, v in enumerate(range(epochs))`: i와 v가 항상 같으므로 `for i in range(epochs)`로 충분.
  - 이동 폭이 lr로 고정이라 lr이 크면 정답 근처에서 왔다 갔다 하고, 작으면 epoch이 많이 필요 → 학습률/epoch 트레이드오프를 보여주는 예제. 실제 딥러닝은 **기울기 크기에 비례**해서 움직이는 경사하강법(0-3) 사용.

### 0-6. HalvingGridSearchCV (`ml/m10_HalvingGridSearchCV_00.py`, m09_00 카피)
- 아이디어(**Successive Halving**): 처음엔 **모든 후보를 적은 데이터로** 빠르게 평가 → 상위 `1/factor`만 남기고 → 남은 후보에 **데이터를 factor배 늘려** 다시 평가 → 반복.
- 데이터: `load_digits` (10클래스), train 1,437개. 파라미터 조합 18+12+12 = **42개**. `StratifiedKFold(5)`.
- 설정: `factor=2`, `min_resources=100`, `max_resources=1437` → 실제 진행 (직접 실행해 확인한 값)

| iter | n_candidates | n_resources | 학습 횟수(×5fold) |
|---|---|---|---|
| 0 | 42 | 100 | 210 |
| 1 | 21 | 200 | 105 |
| 2 | 11 | 400 | 55 |
| 3 | 6 | 800 | 30 |
| | | **합계** | **400** (+ refit 1) |

  - 다음 단계는 1,600 > max_resources(1,437)라 4번에서 멈춤 (`n_possible_iterations=4` < `n_required_iterations=6`) → 마지막에 남은 6개 중 best 선택 후 `refit=True`로 train 전체 재학습.
  - 같은 42개를 GridSearchCV로 돌리면 42×5 = 210번이지만 매번 **1,437개 전체**로 학습 → Halving은 횟수는 많아도 대부분 작은 데이터라 빠름.
- `min_resources=100` 주석의 `2 × cv × 클래스 수 = 2×5×10 = 100`: sklearn이 `min_resources='smallest'`일 때 분류 문제에 쓰는 공식과 같음 (fold마다 클래스가 최소 2개씩 들어가게). 기본값은 `'exhaust'`(마지막 iter가 max_resources를 최대한 쓰도록 역산).
- import: 코드처럼 `sklearn.model_selection._search_successive_halving`(밑줄 = 내부 모듈)에서 가져와도 동작하지만, 공식 방법은
  ```python
  from sklearn.experimental import enable_halving_search_cv  # noqa (실험 기능 활성화)
  from sklearn.model_selection import HalvingGridSearchCV
  ```
- `best_score_`: 마지막 iter의 CV 점수(작은 데이터 기준일 수 있음) → 최종 성능은 `model.score(x_test, y_test)`로 판단.
- **탐색 3종 비교**: Grid(전수, 정확·느림) / Randomized(`n_iter`개 무작위, 빠름·최적 보장 X) / Halving(전 후보를 소량 데이터로 시작해 걸러냄, 빠름·초반 소량 데이터에서 탈락한 좋은 후보를 놓칠 수 있음).

**D3.** weights 4개(층 2개 × kernel+bias) 그대로, trainable_weights 0개.

**D4.** ① sigmoid ② Leaky ReLU ③ ELU ④ SiLU(Swish).

**D5.** 클래스가 2개일 때 softmax는 sigmoid와 같은 형태가 됨(softmax의 이진 버전이 sigmoid). `Dense(2, softmax)`면 y를 원-핫으로 → `categorical_crossentropy`, 정수 라벨이면 `sparse_categorical_crossentropy`.

**E1.** 문서 로드 → 청킹 → 임베딩 → 벡터DB 저장 → 질문으로 검색 → 검색 결과를 프롬프트에 붙여 LLM 답변 생성.

**E2.** 같은 문서가 sqlite에 중복 누적 → 검색 결과에 같은 청크가 반복. 재생성 전 DB 폴더 삭제 또는 ID로 관리.

**E3.** BM25: 키워드 일치 / 벡터: 의미 유사도 / 하이브리드: 두 점수를 가중 결합(EnsembleRetriever).

**E4.** 벡터DB 파일은 용량이 크고(수 MB 바이너리) 코드로 다시 만들 수 있는 산출물이라 저장소에 둘 필요가 없음. `git rm -r --cached _db` (추적만 해제, 로컬 파일 유지) + `.gitignore`에 `_db/` 추가.

**E5.** `add_messages`: 새 메시지를 기존 리스트에 이어 붙이는 리듀서. `tools_condition`: 마지막 AI 메시지에 tool call이 있으면 `tools` 노드로, 없으면 END.

**E6.** 그 키에 리듀서(`Annotated[list, operator.add]` 등)를 지정해야 함. 없으면 동시 업데이트 충돌 에러.

**G1.** 경사하강법은 `w = w − lr × 기울기`로 loss를 줄임 → lr이 너무 작으면 느리고(keras79에서 1000 epoch 필요), 너무 크면 진동/발산(gradient2에서 lr≥1) → 그래서 정체될 때 lr을 줄이는 ReduceLROnPlateau를 쓰고 → Adam 같은 옵티마이저는 파라미터별로 이동 폭을 자동 조절(모멘텀 + 적응적 학습률)해 lr 선택 부담을 줄임.

**G2.** 예) `train_test_split(stratify=y)` → 스케일러 train fit / test transform → `all_estimators` + `cross_val_score(StratifiedKFold)`로 후보 선정 → 조합이 적으면 Grid, 많으면 Randomized, 데이터가 크고 조합도 많으면 Halving → `best_estimator_`로 test에서 한 번만 평가(accuracy).

**G3.** `hist.history`: 학습 후 직접 그래프를 그려야 함, 가장 간단 / TensorBoard: 학습 중 실시간·여러 실험 비교·그래프/히스토그램까지 시각화 / ModelCheckpoint: 시각화가 아니라 **가장 좋은 시점의 모델 파일을 저장**하는 용도.
