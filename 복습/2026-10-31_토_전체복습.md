## Part 0. 가장 최근 추가분 (10-19 ~ 10-23)

### 정리
- **LangGraph 기본 구조** (`LG/lg01~lg09`)
  - `State`: `TypedDict`로 정의. 타입 힌트일 뿐 **강제성은 없음**.
  - `Annotated[list, add_messages]`: `add_messages`가 **Reducer** 역할 → 메시지를 덮어쓰지 않고 **append**. 단, **id가 같으면 덮어씀**.
  - `Node`(함수) → `Edge`(연결). `START`, `END` 사용. `StateGraph(State)` → `add_node` → `add_edge` → `compile()`.
  - **Tool calling**: `TavilySearch`(웹 검색) → `llm.bind_tools(tools)` → `ToolNode(tools)` + `add_conditional_edges('chatbot', tools_condition)`. tool_calls가 있으면 `tools`, 없으면 `END`. 그리고 `tools → chatbot` 엣지로 되돌아와 결과를 LLM이 요약.
  - **Memory**: `InMemorySaver()` → `compile(checkpointer=memory)` → 호출 시 `config={"configurable": {"thread_id": "user01"}}`. **같은 thread_id**여야 대화를 기억.
  - **병렬 실행/병합** (`lg09`): `START → search`, `START → analysis`를 동시에 걸고, 둘 다 `merge`로 연결 → merge는 두 노드가 모두 끝난 뒤 실행. merge 노드에서 두 결과를 프롬프트로 묶어 LLM이 최종 답변 작성.
- **XGBoost 피처 중요도** (`ml/m01_*`)
  - `feature_importances_`는 **F-score(분기에 사용된 빈도)** 기반, `get_booster().get_score(importance_type='gain')`은 **손실 개선량** 기반 (실질적 성능 기여).
  - `train_test_split(..., stratify=y)`는 **분류에서만** 사용 (회귀 ✗).
  - 분류 모델 `score()` = accuracy, 회귀 모델 `score()` = R².
- **WSL** (`wsl.txt`): `wsl --install -d Ubuntu-24.04 --name 이름`, `wsl -l -v`(설치 확인), `wsl -l -o`(설치 가능 목록), `wsl.exe -d 이름`(실행).

## Part 2. Keras 기초 ~ 회귀/분류 (`keras/keras01~32`)

### 핵심 정리
1. **딥러닝 코드 4단계 틀**: `#1 데이터 → #2 모델구성 → #3 컴파일·훈련 → #4 평가·예측`.
2. **데이터 분리**: `train/test`, 그 다음 `validation`(`validation_split` 또는 `train_test_split` 한 번 더). 평가 지표는 회귀 → `R2`, `RMSE`; 분류 → `accuracy`.
3. **스케일링** (`keras27~28`): `MinMax`, `Standard`, `MaxAbs`, `Robust`.
   - **`fit`은 train에만**, test는 `transform`만 (`fit_transform(x_train)` / `transform(x_test)`). test에 fit하면 데이터 누수.
   - `RobustScaler`는 중앙값·IQR 사용 → **이상치에 강함**.
4. **출력층·loss 조합** (`keras21~23`)

   | 문제 | 출력층 | loss |
   |---|---|---|
   | 회귀 | `Dense(1)` | `mse` |
   | 이진분류 | `Dense(1, sigmoid)` | `binary_crossentropy` |
   | 다중분류 | `Dense(클래스수, softmax)` | `categorical_crossentropy` (원핫) / `sparse_categorical_crossentropy` (정수 라벨) |
5. **과적합 대응**: `EarlyStopping(monitor='val_loss', patience, restore_best_weights=True)`, `Dropout`, 스케일링.
6. **저장/불러오기** (`keras29~32`): `model.save()`는 구조+가중치(+컴파일 정보), `save_weights`는 가중치만. `ModelCheckpoint(save_best_only=True)`로 **val_loss가 가장 좋은 시점** 저장.
7. **함수형 모델** (`keras34`): `Input` → 레이어(이전 출력) → `Model(inputs, outputs)`. 다중 입력/출력, 분기·합치기 가능.
8. **GPU 확인** (`keras35`, `gpu세팅.txt`): `tf.config.list_physical_devices('GPU')`. (MNIST 기준 CPU 558초 vs GPU 134초)

## Part 3. CNN (`keras/keras36~43`)

### 핵심 정리
- **데이터 차원**: DNN 2차원, RNN 3차원, CNN 4차원 `(데이터수, 가로, 세로, 채널)`. 모델의 `input_shape`는 데이터수를 뺀 `(28, 28, 1)`.
- 이미지는 0~255 → `/255.`로 MinMax. (이미지에서는 MinMax와 MaxAbs 결과 동일)
- **Conv2D 파라미터 수** = `필터수 × (커널가로 × 커널세로 × 입력채널 + 1)`
- **padding='same'**: 출력 크기를 입력과 동일하게 유지. `valid`는 패딩 없음(크기 감소).
- **stride**: 커널 이동 간격. 크게 하면 출력 크기가 크게 줄어듦.
- **MaxPooling**: 보통 Convolution 뒤에 사용, 특징을 요약하고 크기 감소.
- **GAP(GlobalAveragePooling)**: `Flatten` 자리에 사용 → 파라미터 감소·속도 향상. 뒤에 Dense 한두 개를 붙이는 것이 성능에 좋음.
- 데이터셋: mnist(11), fashion_mnist(12), cifar10(13), cifar100(14). 다중분류는 `to_categorical`/`OneHotEncoder`(sklearn은 `y.reshape(-1,1)` 필요, `sparse_output=False`).
- `keras41`: 같은 이미지 데이터를 **DNN**으로 처리(Flatten 또는 reshape) 후 CNN과 비교. `keras42`: 정형 데이터를 CNN으로 처리(reshape로 4차원화). `keras43`: CNN을 함수형으로.

## Part 4. 이미지 데이터 다루기·증강 (`keras/keras44~51`)

### 핵심 정리
- **`ImageDataGenerator`**: `flow_from_directory`로 폴더명을 라벨로 사용(**알파벳순** 0, 1, …). 반환은 Iterator → `xy[0][0]`(첫 배치 x), `xy[0][1]`(첫 배치 y). 배치 수를 넘는 인덱스는 에러(160장/배치10 → 0~15까지).
- **npy 저장/로드** (`keras45~47`): 한 번 변환한 이미지를 `np.save`/`np.load`로 저장해 속도 향상.
- **`img_to_array`** (`keras48`): PIL 이미지 → numpy.
- **증강(augmentation)** (`keras50~51`): `horizontal_flip`, `vertical_flip`, `width/height_shift_range`, `rotation_range`, `zoom_range`, `shear_range`, `fill_mode`. **증강은 train에만** 적용하는 것이 원칙, `flow()`로 numpy 데이터를 증강 후 배치 생성.
- 임의 이미지를 직접 모델에 넣어 예측해보는 실습(`keras49`: 내가 고양이상인가 / 남자·여자상).

## Part 5. 옵티마이저·학습률 (`keras/keras52~53`)

### 핵심 정리
- `Adam`, `SGD`, `RMSprop` 등 옵티마이저 + **`learning_rate`**(Keras 기본 `0.001`) 조절 실험. 너무 크면 발산/불안정, 너무 작으면 학습이 느림.
- **`ReduceLROnPlateau`**: `val_loss`가 개선되지 않으면 학습률을 `factor` 배로 감소(`patience`, `factor`, `min_lr`). 노트의 결과: california에서 lr 0.01 → 92초, ReduceLR 적용 시 25초로 시간 단축.
- 같은 흐름을 모든 데이터셋(회귀·분류·이미지)에 반복 적용해 비교.

## Part 6. RNN / LSTM / Conv1D (`keras/keras54~59`, `keras2/keras64~68`)

### 핵심 정리
- **시계열 → 지도학습 변환**: 슬라이딩 윈도우로 `(7,3)` 형태로 만들고 `reshape(7,3,1)` → `(samples, timesteps, features)` (`keras56_split`).
- **RNN 입력/출력**: 3차원 입력 → 2차원 출력(바로 Dense 연결 가능). `input_shape=(timesteps, features)`.
- **파라미터 수**
  - SimpleRNN: `units × (features + units + 1)`
  - LSTM: `4 × units × (features + units + 1)` (게이트 4개)
  - GRU: `3 × …` (※ Keras 3 기본은 `reset_after=True`라 bias가 하나 더 붙어 약간 다름)
  - Bidirectional: 위의 **2배** (래퍼일 뿐 모델이 아님)
- **`return_sequences=True`**: 모든 시점의 출력 유지 → 3차원 출력(다음 RNN/LSTM에 연결, 다대다). LSTM을 무작정 여러 층 쌓는다고 좋아지지는 않음.
- **Conv1D**: 시계열에서도 잘 작동. 입력·출력 모두 3차원 → Dense에 연결하려면 `Flatten` 또는 `GAP`. `kernel_size`는 시계열의 timestep 묶음 크기에 해당.
- `keras58~59`: Jena 기후 데이터 시계열 실습. `keras66`: Jena + CNN.
- 층별 비교 (`모델종류.txt`)

  | | Dense | Conv2D | Conv1D | RNN | Embedding |
  |---|---|---|---|---|---|
  | 입력 차원 | 2↑ | 4 | 3 | 3 | 2 |
  | 출력 차원 | 2↑ | 4 | 3 | 2 | 3 |
  | Flatten 필요 | △ | O | O | X | X |

## Part 7. 자연어·임베딩·구조 변형 (`keras2/keras60~70`)

### 핵심 정리
- **Tokenizer** (`keras60`): `fit_on_texts` → `word_index`. **빈도수 높은 순**으로 번호, 빈도 같으면 먼저 나온 순. `texts_to_sequences`로 수치화. 어절 단위 방식은 실무용이 아님.
- **수치화만으로는 부족**: 2번 토큰이 1번 토큰의 2배가 아니므로 → **원핫인코딩**(pandas `get_dummies`, sklearn `OneHotEncoder`, keras `to_categorical` — Tokenizer는 0이 없으니 주의) 또는 **Embedding**.
- **패딩**: `pad_sequences`로 길이 통일(`padding='pre'` 기본, `maxlen`).
- **Embedding 레이어** (`keras61`): `Embedding(단어사전 크기, output_dim)` — 입력 2차원 → 출력 3차원. 뒤에 LSTM/Flatten 연결.
- **sparse_categorical_crossentropy** (`keras63`): 정수 라벨을 원핫 없이 그대로 사용. 원핫 + categorical 과 성능 차이는 없음.
- **Reshape 레이어** (`keras65`): 모델 안에서 shape 변경 — **순서와 값은 바뀌면 안 되고 모양만** 바뀜 (원소 수 동일해야 함).
- **앙상블(다중 입력)** (`keras69`): 모델 2개(각자 `Input`)를 `Concatenate`로 합치고 Dense. `train_test_split`에 x1, x2, y를 한 번에 넣어 같은 인덱스로 분할. `concatenate`(함수)와 `Concatenate`(클래스)는 기능 동일.
- `keras70`: 상관관계(correlation), 예측, 주가 맞추기 실습.

## Part 8. 전이학습 (`keras2/keras71~76`, `xception_cifar100.py`)

### 핵심 정리
- **`model.trainable = False`** → 동결(freeze): `weights`는 그대로 6개지만 `trainable_weights`는 0개. 부분 동결은 `model.layers[i].trainable = False`.
- **Pre-trained model**: `VGG16(weights='imagenet', include_top=False, input_shape=(32,32,3))`.
  - `include_top=True`: 분류용 FC(Flatten+Dense)까지 포함, 입력은 224×224×3 고정, 파라미터 1.38억.
  - `include_top=False`: FC 제거, **input_shape 변경 가능**. 그 위에 Flatten/GAP + Dense를 직접 붙임.
- **Feature Extraction**(동결 후 특징 추출기로 사용) vs **Fine-tuning**(일부 층만 풀어서 재학습).
- `keras75`: VGG, ResNet, DenseNet, Inception, MobileNet, EfficientNet, Xception 등의 가중치 개수를 비교. `keras76`: cifar10/100에 여러 모델 적용.

## Part 9. RAG (`RAG/rag01~23`)

### 핵심 정리
- **RAG** = Retrieval(검색, 벡터DB) + Augmented(질문에 자료를 붙임) + Generation(근거 기반 답변 생성).
- **환경변수**: 키는 코드에 쓰지 않고 `.env` + `load_dotenv()` → `os.environ["KEY"].strip()` (`.strip()`은 공백·개행 오타 방지).
- **LCEL**: `chain = prompt | model | parser` (`|`는 연산자 오버라이딩). `chain.invoke({"topic": ...})`.
- **문서 처리 파이프라인**: `TextLoader`/`PyPDFLoader`(PDF는 **페이지별** Document, `metadata`+`page_content`) → `RecursiveCharacterTextSplitter(chunk_size, chunk_overlap)` (**overlap < size**) → 임베딩 → 벡터DB.
- **임베딩**: OpenAI `text-embedding-3-small`(1536차원) / `-large`(3072차원), HuggingFace `BAAI/bge-m3`, `Qwen3-Embedding-0.6B`(로컬, `device`: cpu/cuda).
- **Chroma vs FAISS** (`VectorDB.txt`)

  | | Chroma | FAISS |
  |---|---|---|
  | 특징 | 문서 원문·메타데이터·필터·추가/수정/삭제 함께 관리 | 벡터를 **매우 빠르게** 찾는 데 집중 (책 위치번호만 찾음) |
  | 저장 | `persist_directory`, `collection_name` → `chroma.sqlite3` (반복 실행 시 **누적**) | `save_local(folder_path, index_name)` |
  | 거리 | — | `IndexFlatL2`(유클리드). 인덱스 차원은 임베딩 차원과 동일해야 함 |
  | 선택 | 메타데이터·관리 필요 시 | 대용량·속도 중시 |
- **검색 방식** (`rag23`): **BM25**(키워드 기반, 단어 일치) / **벡터검색**(의미 유사도) / **하이브리드(앙상블)** = 둘을 결합.
- **Gradio**: 챗봇 UI, 히스토리 유지, 문서 확인·유사도·프롬프트 확인 화면 (`rag15~22`).
