## 1. 핵심 정리 ① — GridSearchCV (`ml/m08_GridSearchCV_00/01/02.py`)

### 1-1. 전체 흐름
```python
x_train, x_test, y_train, y_test = train_test_split(x, y, train_size=0.8,
                                   random_state=333, stratify=y)   # 분류라서 stratify
kfold = StratifiedKFold(n_splits=5, shuffle=True, random_state=333)

parameters = [
  {'n_estimators':[100,500], 'max_depth':[6,10,12], 'learning_rate':[0.1,0.01,0.001]},  # 2×3×3 = 18
  {'max_depth':[6,8,10,12], 'learning_rate':[0.1,0.01,0.001]},                         # 4×3   = 12
  {'min_child_weight':[2,3,4,10], 'learning_rate':[0.1,0.01,0.001]},                    # 4×3   = 12
]                                                                                       # 합계  = 42

model = GridSearchCV(XGBClassifier(), parameters, cv=kfold,
                     verbose=1, n_jobs=-1, refit=True)
model.fit(x_train, y_train)
```

### 1-2. 꼭 기억할 포인트
| 항목 | 내용 |
|---|---|
| **조합 수 계산** | 딕셔너리 **안**은 곱하기(×), 리스트의 딕셔너리 **끼리**는 더하기(+) → 18 + 12 + 12 = **42개 후보** |
| **총 학습 횟수** | 42 후보 × 5 fold = **210번** + `refit=True`면 최적 조합으로 전체 train 재학습 **1번** = 211번 |
| `n_jobs=-1` | CPU 코어를 **전부** 사용 (병렬) |
| `verbose=1` | `Fitting 5 folds for each of 42 candidates, totalling 210 fits` 같은 진행 메시지 출력 |
| `refit=True` (기본값) | 최적 파라미터로 **train 전체**에 다시 fit → 그래서 `model.score()`, `model.predict()`를 바로 쓸 수 있음 |
| `best_estimator_` | 최적 파라미터가 들어간 **모델 객체 자체** |
| `best_params_` | 최적 파라미터 **딕셔너리**만 |
| `best_score_` | 최적 조합의 **교차검증(train 안의 검증 fold) 평균 점수** |
| `model.score(x_test, y_test)` | refit된 최적 모델로 **test** 평가 (분류=accuracy, 회귀=R²) |
| `time.perf_counter()` | 시간 측정용 고정밀 타이머 → `end - start` |

> 💡 코드 주석의 `best_score_ # train 데이터로 테스트한것중 best -> 과적합되있음`을 조금 더 정확히 말하면:
> best_score_는 train 데이터를 **나눠서 만든 검증 fold**의 점수예요 (훈련한 데이터로 그대로 채점한 건 아님).
> 그래도 **42개 중 가장 잘 나온 것만 골랐기 때문에** 낙관적으로(높게) 나오기 쉽고,
> 처음 보는 데이터에서의 진짜 성능은 **`model.score(x_test, y_test)`** 로 확인해야 합니다.

### 1-3. 분류(digits) vs 회귀(diabetes) 차이
| | `m08_00` / `m08_01` (digits) | `m08_02` (diabetes) |
|---|---|---|
| 모델 | `XGBClassifier` | `XGBRegressor` |
| split | `stratify=y` | `# stratify=y` (주석 처리) |
| CV | `StratifiedKFold` | `KFold` |
| score 의미 | accuracy | R² |

- **회귀는 y가 연속값**이라 "클래스 비율을 맞춘다"는 개념이 없음 → `stratify`, `StratifiedKFold`를 쓰지 않음.
- `m08_01`은 `max_depth`를 `[10, 15, 20]`으로 바꾸고 `refit`은 명시하지 않음(기본값 True라 동작은 같음).

### 2-2. 다섯 가지 규칙
1. **`import` 하면 그 파일이 위에서부터 한 번 실행된다.**
   `p01_car.py` 맨 아래의 `drive()` 호출 때문에 `import p01_car`만 해도 "운전하다"가 찍힘.
2. **`__name__`** : 직접 실행한 파일 → `'__main__'`, import된 파일 → **파일 이름(모듈 이름)** (`'p11_car'`).
3. **`if __name__ == '__main__':`** 안의 코드는 **직접 실행할 때만** 동작. import될 때는 건너뜀.
   → 그래서 "테스트용 코드"는 이 블록 **안에** 넣어야 함. (`p21_car.py`는 `drive()`를 블록 밖에도 한 번 써서 반쪽짜리 예시예요)
4. **같은 모듈은 한 프로세스에서 딱 한 번만 실행된다** (`sys.modules`에 캐싱). 두 번째 import부터는 출력 없음.
5. **전역변수는 모듈마다 따로 있다.** 함수는 *자기가 정의된 파일*의 전역변수를 본다.
   `p31_sample.test()`는 `p32`에서 `x = 222`를 해도 항상 **`x : 111`** 출력.

## 4. 정답 및 해설

<details>
<summary>A. GridSearchCV 개념</summary>

- **A1.** 첫 dict 3×2 = 6, 둘째 dict 2×3×1 = 6 → **12개 후보**. fit = 12×5 = 60 + refit 1 = **61번**.
- **A2.** `best_estimator_`: 최적 파라미터로 refit된 **모델 객체** / `best_params_`: 최적 파라미터 **dict** / `best_score_`: 최적 조합의 **CV 검증 평균 점수**.
- **A3.** 에러 발생 (`refit=False`면 최종 모델을 학습하지 않으므로 `score`/`predict`를 쓸 수 없음 → AttributeError 류). `best_params_`, `best_score_`는 확인 가능.
- **A4.** **X**. train을 KFold로 나눈 **검증 fold**의 평균 점수. test는 fit에 전혀 쓰이지 않음.
- **A5.** y가 **연속값(회귀)** 이라 클래스 비율을 유지한다는 개념이 없음. 연속값에 `StratifiedKFold`를 쓰면 에러/경고가 나거나 의미가 없음.
- **A6.** **R²** (회귀 모델의 기본 `.score()`).
- **A7.** 모든 CPU 코어로 병렬 실행. **속도만** 달라지고 결과는 같음 (같은 random_state 기준).
</details>

### ✅ 오늘의 한 줄 요약
- **GridSearchCV** = (dict 안은 곱, dict끼리는 합) 후보 × fold 수만큼 학습 → `best_*`는 train 안의 CV 결과, 진짜 성능은 **test score**.
- **import** = 처음 한 번만 파일 전체 실행 · `__name__`으로 직접 실행 여부 구분 · 전역변수는 **모듈마다 따로**.
