## 1. 핵심 정리

### 1-1. K-Fold 교차검증 (m02)
- `KFold(n_splits=5, shuffle=True, random_state=333)` : 데이터를 5조각으로 나눠 **조각마다 한 번씩 검증용**으로 사용.
- `cross_val_score(model, x, y, cv=kfold)` : 5번 **fit → score를 자동 수행**하고 점수 5개를 배열로 반환 (그래서 `model.fit`을 따로 안 씀).
- 기본 score: **분류 = accuracy, 회귀 = R²** (코드 출력에 'acc'라고 써도 회귀에서는 R²임).
- 평균(`np.mean(scores)`)이 모델의 대표 성능. 폴드별 점수 편차가 작을수록 안정적.
- 결과 비교 (코드 주석 기준)
  | 데이터 | 모델별 평균 |
  |---|---|
  | iris | DecisionTree 0.95 |
  | california(R²) | DecisionTree 0.61 < RandomForest 0.81 ≈ GradientBoosting 0.81 ≈ XGB 0.8 |
  | kaggle_bike(R²) | XGB 0.23 < RF 0.27 < GradientBoosting 0.32 (전반적으로 낮음) |
  | santander(acc) | DecisionTree 0.83 < RF 0.9 ≈ GB 0.9 < XGB 0.91 |
- santander는 타깃 비율이 `0: 179902 / 1: 20098` 로 **불균형** → `train_test_split(stratify=y)` 사용.

### 1-2. train/test split 후 train에만 K-Fold (m03)
- 순서: ① `train_test_split` → ② 스케일러 `fit_transform(x_train)`, `transform(x_test)` → ③ train에만 `cross_val_score` → ④ test로 최종 평가.
- 스케일러는 **train에만 fit** (test 정보 누수 방지).
- `cross_val_predict` : 각 샘플이 검증 폴드일 때의 예측값을 모아 반환.
- ⚠️ 코드의 `cross_val_predict(model, x_test, y_test, cv=kfold)` 는 test 안에서 다시 폴드를 나눠 학습/예측하는 것이므로, "train으로 학습한 모델로 test를 예측"하는 것과 **다르다**. (정석: `model.fit(x_train,y_train)` → `model.predict(x_test)`)
- ⚠️ california(회귀)에 `accuracy_score`를 쓰면 연속값 타깃이라 오류 → 회귀는 `r2_score`, RMSE 사용.

### 1-3. 모든 모델 돌려보기: `all_estimators` (m04)
- `from sklearn.utils import all_estimators`
- `all_estimators(type_filter='classifier' | 'regressor')` → `(이름, 클래스)` 튜플의 리스트 (sklearn 1.9.1: 분류기 44개 주석).
- `for name, model in all:` 로 언패킹, `model()` 로 **인스턴스 생성**.
- 필수 인자가 필요한 모델(예: 다른 estimator를 인자로 받는 앙상블/Pipeline류)은 `model()` 단계에서 오류 → 인스턴스 생성도 `try` 안에 넣어야 함.
- `warnings.filterwarnings('ignore')` 로 경고 숨김.
- 변수명 `all`은 파이썬 내장함수 `all()`을 가리므로 주의.
- m04_regressor 파일은 데이터가 여전히 iris(분류 데이터) → 회귀기에 쓰려면 회귀 데이터로 바꿔야 의미 있음.

### 1-4. all_estimators + K-Fold 결합 (m05)

## 3. 정답 및 해설

1. **X** — `cross_val_score` 가 내부에서 fold마다 복제 모델로 fit/score를 수행.
2. **②** 나누기 전에 섞음 (클래스 비율 유지는 StratifiedKFold).
3. **②** 회귀 기본 score는 R².
4. `train_test_split(stratify=y)`, `StratifiedKFold` (분류에서 `cv=정수` 로 주면 기본적으로 StratifiedKFold 사용).
5. **②** `(name, class)` 튜플 리스트.
6. **②** FP8 = 1바이트/파라미터 → 약 8GB (FP16이면 약 16GB).
7. Hugging Face 인증 토큰이 공개 저장소에 노출되지 않도록.
8. **XGB** — 평균이 더 높고 폴드 간 편차도 작음(0.90~0.91).
9. test 데이터의 평균/표준편차 등 정보가 학습 과정에 섞이면 평가가 과대평가됨. 스케일러는 train 통계로만 fit하고 test에는 `transform` 만.
10. ① `cross_val_predict` 를 test 데이터로 다시 학습/예측 → train으로 학습한 모델의 예측이 아님. ② 회귀 문제에 `accuracy_score`(분류용) 사용 → 연속값이라 오류. `r2_score` 사용.
11. 필수 인자가 있는 모델은 인스턴스 생성 단계에서 예외가 발생해 프로그램 전체가 멈춤.
12. 파이썬 내장 `all()` 을 덮어써서 이후 `all(...)` 사용 시 오류. (예: `models`, `allAlgorithms`)
13. iris는 분류 데이터(라벨 0/1/2)라 회귀 평가(R²)가 의미 없음 → california 등 회귀 데이터를 써야 함.
14. 데이터 분할 우연에 덜 민감(점수 신뢰도↑), 모든 데이터를 학습·검증에 활용, 폴드별 편차로 안정성 확인 가능.
15. K-Fold: 모델/하이퍼파라미터 선택용 검증 점수(train 안에서). test: 선택이 끝난 뒤 **한 번** 하는 최종 일반화 성능.
16. 예: 파생 변수(시간/요일 등) 추가, 하이퍼파라미터 튜닝, 타깃 로그 변환, 이상치 처리, 다른 모델/앙상블.
17. `--devices` 사용할 NPU 번호(status로 확인), `--host 0.0.0.0` 모든 네트워크 인터페이스에서 접속 허용, `--port` 서버 포트.
