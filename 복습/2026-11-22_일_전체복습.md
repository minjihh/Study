## 2. 🖼️ 이미지 데이터 파이프라인 (keras44 ~ 51)

### 2-1. `ImageDataGenerator` + `flow_from_directory` (`keras/keras44_ImageDataGenerator1.py`)

- 폴더 구조(`train/ad`, `train/normal`)를 그대로 **클래스**로 읽습니다. `Found 160 images belonging to 2 classes.`
- 반환값은 배열이 아니라 **`DirectoryIterator`**입니다. 인덱싱하면 `(x배치, y배치)` 튜플이 나옵니다.
  - `xy_train[0][0].shape` → `(10, 100, 100, 1)` (batch=10, grayscale라서 채널 1)
  - `xy_train[0][1].shape` → `(10,)` (`class_mode='binary'`)
  - 160장 ÷ 10 = **16배치**이므로 `xy_train[16]`부터 IndexError가 납니다.
- **train에는 증강과 스케일링, test에는 `rescale`만 적용**합니다. test 이미지를 뒤집거나 돌리면 평가가 왜곡되기 때문입니다.
- test는 `shuffle=False`로 둡니다. 예측 순서와 정답 순서를 맞춰야 하기 때문입니다.

⚠️ **코드 보충**: `zoom_range = 1.2`
- 실수 하나를 주면 Keras는 범위를 `[1 - 1.2, 1 + 1.2] = [-0.2, 2.2]`로 해석합니다. 음수 배율이 들어가는 이상한 범위입니다.
- 보통은 `zoom_range=0.2`(0.8~1.2배)처럼 작은 값을 씁니다.

### 2-2. 통배치로 꺼내 `.npy`로 저장하기 (`keras/keras45_01_brain_save_npy.py`)

- `batch_size=160`(전체 장수)으로 두면 `xy_train[0][0]` 하나에 **전체 데이터**가 들어옵니다.
- 이것을 `np.save`로 저장해 두면 다음부터는 이미지 디코딩 없이 `np.load`만으로 바로 학습할 수 있습니다(keras45_02, 47).
- 주의: 저장 경로가 `kaggle_cat_dog_npy/`인데 파일 내용은 **brain** 데이터입니다. 이름과 실제 내용이 다른 경우입니다.

⚠️ **모델 구조 함정**: Flatten **앞에** `Dense(64)`가 있습니다.
```python
Conv2D(64,(3,3),padding='same')  ×3   # (150,150,64)
Dense(64)                             # (150,150,64)  ← 마지막 축(채널)에만 적용됨
Flatten()                             # 1,440,000
Dense(1, sigmoid)                     # 파라미터 1,440,001개!
```
4차원 텐서에 Dense를 붙이면 **마지막 축에만** 적용되고, 결과는 픽셀마다 따로 계산한 1×1 conv와 같습니다.
그 뒤 Flatten에서 144만 차원이 생기기 때문에 출력층 하나에 파라미터가 144만 개 붙습니다. 이 파일 주석에 적힌 "brain data는 dense layer가 많으면 학습이 잘 안 됨"과도 연결됩니다.
Pooling이나 GAP으로 공간 크기를 먼저 줄이는 이유가 바로 이것입니다.

### 2-3. 증강으로 데이터 늘리기 (`keras/keras51_augment1_fashion.py`)

```python
randidx = np.random.choice(60000, size=40000, replace=False)   # 중복 없이 4만 개 인덱스
x_augmented = x_train[randidx].copy()                           # .copy()로 원본과 분리
x_augmented = x_augmented.reshape(40000, 28, 28, 1)            # flow는 4D 입력 필요
xy_augmented = datagen.flow(x_augmented, y_augmented,
                            batch_size=40000, shuffle=False).next()[0]
...
x_train = np.concatenate((x_train, x_augmented))                # (100000, 28, 28, 1)
```

🐞 **이 코드의 진짜 버그 (중요!)**
- 주석에는 "위 코드를 실행함으로서 x_augmented에도 datagen이 적용됨"이라고 적혀 있습니다. **틀린 설명입니다.**
- `.next()[0]`은 **새 배열을 반환**하고, 그 결과는 `xy_augmented`라는 **다른 변수**에 저장됩니다. `x_augmented`는 바뀌지 않습니다.
- 그래서 `concatenate`에 들어가는 `x_augmented`는 다음 상태입니다.
  1. 증강이 전혀 **적용되지 않은 단순 복제본**입니다. 4만 장을 똑같이 한 번 더 넣는 셈입니다.
  2. `rescale`도 적용되지 않아서 **0~255 범위**입니다. 반면 `x_train`은 `datagen_origin`을 거쳐 **0~1 범위**입니다.
  → 한 학습셋 안에 **스케일이 다른 데이터가 섞이게** 됩니다.
- 고치는 방법: `x_augmented = datagen.flow(...).next()[0]`처럼 **같은 변수에 다시 대입**합니다.

## 3. ⚙️ 학습을 돕는 설정 — 옵티마이저 & ReduceLROnPlateau (keras52 ~ 53, keras58)

### 3-1. 옵티마이저 객체로 학습률 지정하기 (`keras/keras52_optimizer01_california.py`)
```python
from tensorflow.keras.optimizers import Adam
model.compile(loss='mse', optimizer=Adam(learning_rate=0.01))   # 문자열 'adam'이면 lr=0.001(기본값)
```
- 문자열 `'adam'`을 쓰면 기본 학습률 0.001이 적용됩니다. 학습률을 바꾸려면 **객체로 생성**해서 넘겨야 합니다.
- `batch_size=4`이면 한 epoch에 `ceil(14447/4) = 3612`번 가중치를 갱신합니다. 그래서 같은 10 epoch라도 매우 느립니다(92초).

### 3-2. ReduceLROnPlateau (`keras/keras53_ReduceLR01_california.py`)
```python
rlr = ReduceLROnPlateau(monitor='val_loss', patience=20, factor=0.5)
es  = EarlyStopping(monitor='val_loss', patience=40, restore_best_weights=True)
```
- `val_loss`가 20 epoch 동안 개선되지 않으면 **lr × 0.5**로 줄입니다.
- **RLR patience < ES patience**여야 의미가 있습니다. 학습률을 낮춰 볼 기회를 먼저 주고, 그래도 개선이 없으면 멈추는 순서입니다.
- 이 파일에서는 `x_val`을 만들어 놓고 실제로는 `validation_split=0.2`를 씁니다. `x_val`은 쓰이지 않는 변수입니다.

🐞 **반대로 설정한 예** (`keras/keras58_kaggle_jena1.py`): `es patience=10`, `rlr patience=20`
→ 10 epoch 정체 시 ES가 먼저 학습을 멈추기 때문에 **RLR은 한 번도 작동하지 않습니다.**

## 4. ⏱️ 시계열 데이터 파이프라인 (`keras/keras58_kaggle_jena1.py`)

목표: 직전 144개 시점(10분 간격, 하루)의 13개 피처로 **다음 144개 시점의 기온**을 예측합니다.

```python
x_data = datasets[:-288].drop(['T (degC)'], axis=1)   # (420263, 13)
y_data = datasets[144:-144]['T (degC)']               # (420263,)  ← x보다 144칸 뒤에서 시작
# 윈도우 i:  x = x_data[i : i+144]  /  y = y_data[i : i+144] (= 원본 i+144 ~ i+287 → "바로 다음 하루")
x_split.shape → (420120, 144, 13)       # 420263 - 144 + 1 = 420120
y_split.shape → (420120, 144)           # ⚠️ 주석의 (420120,)은 틀림
model: SimpleRNN(64, input_shape=(144,13)) → ... → Dense(144)
```

**스케일링 3단계**: 스케일러는 2차원 입력만 받으므로 다음 순서로 처리합니다.
```python
x_train.reshape(-1, 13)  →  scaler.fit(train만) / transform  →  reshape(-1, 144, 13)
```

🐞 **생각해 볼 함정 3가지**
1. `train_test_split`이 기본값 `shuffle=True`로 동작합니다. 윈도우가 1칸씩 겹치기 때문에 train의 윈도우 i와 test의 윈도우 i+1은 143/144가 같은 데이터입니다. 그래서 **test 점수가 실제보다 좋게 나옵니다(누수)**.
2. `validation_data=(x_test, y_test)`로 두면 ES와 RLR이 **test를 보고** 학습 종료 시점을 정합니다. test가 사실상 검증셋이 됩니다.
3. `xy_split` 함수 안에서 매개변수 `x` 대신 전역 변수 `len(x_data)`를 사용합니다. 지금은 우연히 같은 값이라 동작하지만, 다른 데이터를 넣으면 길이가 틀어집니다.

마지막 평가에서는 `x_predict = datasets[-288:-144]`(마지막 날 직전의 하루)로 `y_cor = datasets[-144:]`(마지막 하루)를 예측하고 RMSE를 계산합니다(약 3.5℃).

## 5. 🔤 텍스트 데이터 파이프라인 (keras60 ~ 63)

### 5-1. Tokenizer (`keras2/keras60_Tokenizer1.py`)
```python
text = '나는 지금 진짜 진짜 매우 매우 맛있는 김밥을 엄청 마구 마구 마구 먹었다.'
```
- `word_index`는 **빈도가 높은 순**으로 1번부터 번호를 매깁니다. 빈도가 같으면 먼저 등장한 단어가 앞 번호를 받습니다. **0번은 비워 둡니다**(패딩용).
  → `{'마구':1, '진짜':2, '매우':3, '나는':4, '지금':5, '맛있는':6, '김밥을':7, '엄청':8, '먹었다':9}`
  (기본 필터가 마침표 `.`를 제거하므로 `먹었다.`는 `먹었다`가 됩니다.)
- `texts_to_sequences` 결과는 `[[4, 5, 2, 2, 3, 3, 6, 7, 8, 1, 1, 1, 9]]`입니다(13개 토큰).
- `to_categorical` 결과는 `(1, 13, 10)`입니다. 최댓값 9에 1을 더해 10열이 되고, **0번 열은 항상 0이라 낭비**됩니다.

### 5-2. 패딩과 잘라내기 (`keras2/keras62_1_reuters.py`)
- `reuters.load_data(num_words=1000)`은 빈도 상위 1000개 단어만 남깁니다. 그래서 인덱스는 1000 미만이고, `Embedding(input_dim=1000)`과 맞습니다.
- `x_train`은 길이가 다른 **list들이 담긴 object 배열**입니다. 기사 길이는 최대 2376, 최소 13, 평균 약 145입니다.
- `pad_sequences(maxlen=50, padding='pre', truncating='post')`
  - 짧은 기사는 **앞쪽**을 0으로 채웁니다.
  - 긴 기사는 **뒤쪽**을 잘라 **앞 50단어만** 남깁니다(기본값 `truncating='pre'`는 앞쪽을 잘라냄).
  - 결과는 `(8982, 50)`입니다. 주석의 `(8982, 5)`는 이전 실험값이 남은 것입니다.
- `Embedding(1000, 500, mask_zero=True)`의 파라미터는 1000×500 = **500,000**입니다. `mask_zero=True`이면 0번 패딩은 LSTM 계산에서 제외됩니다.

🐞 **함정**: Embedding 앞에서 `reshape(N, 50, 1)`을 했습니다.
- Embedding은 **(batch, 시퀀스 길이)** 형태의 2D 정수 입력을 받아 `(batch, 50, 500)`을 출력합니다.
- 3D 입력을 넣으면 출력이 `(batch, 50, 1, 500)`인 4D가 되어 다음 LSTM(3D 입력 필요)과 맞지 않습니다.
- **Embedding을 쓸 때는 reshape가 필요 없습니다.** reshape로 3D를 만드는 것은 Embedding 없이 LSTM에 바로 넣던 예전 방식입니다.

### 5-3. `sparse_categorical_crossentropy` (`keras2/keras63_sparse1_mnist.py`)
- y가 `0~9` 정수 그대로(`(60000,)`)여도 됩니다. **원핫 인코딩이 필요 없습니다.**
- 출력층은 그대로 `Dense(10, softmax)`이고, 예측할 때도 `argmax`를 그대로 씁니다.
- `categorical_crossentropy`와 수학적으로는 같은 손실입니다. y 형식만 다릅니다(정수 vs 원핫). 클래스가 많을 때 메모리를 절약할 수 있습니다.
- 참고: 이 파일의 `ModelCheckpoint` 파일명 `'{epoch:4d}-{date:.4f}'`는 `date`가 로그 키가 아니라서 저장 시 오류가 납니다. 다만 `callbacks=[es]`에 mcp가 빠져 있어서 실제로는 문제가 드러나지 않습니다.

## 6. 🌲 트리 모델 Feature Importance (`ml/m01_*`)

- `DecisionTree`, `RandomForest`, `GradientBoosting`, `XGB`는 모두 `.feature_importances_`를 제공하며, **합이 1**이 되도록 정규화되어 있습니다.
- `stratify=y`는 분류 문제에서 클래스 비율을 train/test에 동일하게 유지합니다. 회귀(연속값)에서는 쓰지 않습니다.
- `model.score()`는 분류 모델이면 **accuracy**, 회귀 모델이면 **R²**를 반환합니다.
- XGBoost 중요도 종류 (`m01_03_gain`, `m01_04_그래프`)

  | 타입 | 의미 |
  |---|---|
  | `weight` (= F score) | 그 피처로 **분기한 횟수** → `plot_importance`의 **기본값** |
  | `gain` | 그 피처로 분기했을 때 **손실이 평균적으로 얼마나 줄었는가** → 실질적인 기여도 |
  | `cover` | 그 분기가 영향을 준 샘플 수 |

  - `get_booster().get_score(importance_type='gain')`은 **정규화되지 않은 원값**을 딕셔너리(`{'f0':..}`)로 반환합니다.
  - ⚠️ 코드에서는 `feature_importances_`를 "F 스코어"로 출력합니다. 하지만 최근 xgboost의 sklearn API(트리 부스터)에서 `feature_importances_`의 기본값은 **gain을 정규화한 값**입니다. 엄밀히 말하면 F score(weight)가 아닙니다.

## 7. 📄 문서 데이터 파이프라인 & 하이브리드 검색 (RAG rag19 ~ 23)

### 7-1. PDF 로딩 (`RAG/rag19_PyPDF_1.py`)
- `PyPDFLoader(...).load()`는 `list[Document]`를 반환하며, **페이지 1장이 Document 1개**입니다(Attention 논문은 15개).
- Document는 `page_content`와 `metadata`(source, page 번호)로 구성됩니다.
- `load_and_split(text_splitter=...)`는 로드와 청크 분할을 한 번에 처리합니다.
- `RecursiveCharacterTextSplitter(chunk_size=300, chunk_overlap=100, separators=["\n\n","\n"," ",""])`
  - 문단 → 줄 → 공백 → 글자 순서로 **큰 단위부터** 잘라 보고, 300자를 넘을 때만 더 작은 단위로 자릅니다.
  - `chunk_overlap`은 경계에서 문맥이 끊기지 않게 하는 겹침입니다. 반드시 chunk_size보다 작아야 합니다.

### 7-2. HuggingFace 임베딩 (`RAG/rag20_embedding2_bge-m3.py`, `rag20_embedding3_qwen3.py`)
- `HuggingFaceEmbeddings(model_name=..., model_kwargs={"device":"cpu", "local_files_only":True})`
  - 첫 실행 때 모델을 내려받고, 이후에는 `local_files_only=True`로 **오프라인 캐시**를 사용합니다.
  - bge-m3와 Qwen3-Embedding-0.6B는 둘 다 **1024차원**입니다(OpenAI `text-embedding-3-small`은 1536차원).
  - API 키나 비용 없이 로컬에서 실행할 수 있습니다. 대신 CPU에서는 느립니다.

### 7-3. BM25 vs 벡터 검색 vs 하이브리드 (`RAG/rag23_01~03`)

| | BM25 (`BM25Retriever`) | 벡터 검색 (`Chroma.as_retriever`) |
|---|---|---|
| 원리 | 단어가 **글자 그대로** 겹치는지(TF-IDF 계열 점수) | 임베딩 벡터의 **의미 유사도** |
| 강점 | 고유명사, 코드명, 숫자처럼 정확히 일치해야 하는 검색 | 동의어나 다른 표현("반도체 사업" ≈ "메모리 생산") |
| 약점 | 표현이 조금만 달라도 놓침 | 정확한 키워드가 오히려 묻힐 수 있음 |

- `EnsembleRetriever(retrievers=[bm25, vector], weights=[0.5, 0.5])`는 두 결과를 **순위 기반(Reciprocal Rank Fusion)**으로 합칩니다.
  - 점수 = Σ weightᵢ / (rankᵢ + c), c 기본값 60
  - 두 검색기의 점수 스케일이 달라도 **순위만으로** 합치기 때문에 공정하게 섞을 수 있습니다.
  - 성격이 다른 검색기를 섞는 것이 "하이브리드"입니다. 앙상블은 이보다 더 넓은 개념입니다(주석 내용과 같음).

🐞 **BM25 + 한국어 함정 (중요)**
- BM25Retriever의 기본 토크나이저는 **공백 기준 split**입니다.
- query `"삼성전자의 반도체 사업"`의 토큰은 `삼성전자의`, `반도체`, `사업`입니다.

- 해결: `BM25Retriever.from_documents(texts, preprocess_func=형태소분석기)`처럼 Kiwi나 Okt 같은 **한국어 형태소 분석기**를 넣습니다.

🐞 **rag23_02/03 코드에서 확인할 점**

## 8. 🏗️ 전이학습 모델 목록 (`keras2/keras75_All_TransferLearning.py`)
- `len(model.weights)`는 파라미터 **개수가 아니라 가중치 텐서(kernel, bias, BN의 gamma/beta/mean/var 등) 개수**입니다.
- `trainable=True`이면 `len(trainable_weights)`가 BN의 moving mean/var만큼 `len(weights)`보다 적습니다. BN 통계값은 원래 학습 대상이 아니기 때문입니다.
- `model_list = [VGG16(), ...]`처럼 **괄호를 붙이면** 리스트를 만드는 순간 19개 모델을 모두 생성하고, ImageNet 가중치도 전부 내려받습니다. 메모리와 시간이 많이 듭니다. 클래스 자체(`VGG16`)를 리스트에 넣고 for문 안에서 생성하면 더 가볍습니다.
- `for model in model_list:`가 위에서 만든 `model`(Xception) 변수를 덮어씁니다.

- **E3.** stratify는 **클래스(범주)** 비율을 맞추는 기능입니다. 연속값 y는 값이 거의 모두 달라서 그룹을 만들 수 없고, 오류가 납니다(각 값이 1개뿐인 클래스가 됨).

- **F2.** 문단(`\n\n`) → 줄(`\n`) → 공백 → 글자 순서로, **큰 단위로 먼저 자르고** chunk_size를 넘을 때만 더 작은 단위로 내려갑니다. overlap은 청크 경계에서 문장이나 문맥이 잘려 의미가 사라지는 것을 막습니다.
- **F3.** **1개(7번)**뿐입니다. 공백 기준 토큰화라서 `삼성전자의`≠`삼성전자는`, `반도체`≠`반도체를`/`반도체는`처럼 **조사가 붙으면 다른 단어**가 됩니다. 해결책은 `preprocess_func`에 Kiwi나 Okt 같은 한국어 **형태소 분석기**를 넣는 것입니다.
- **F4.** 점수 자체가 아니라 **순위**를 사용하는 가중 RRF로 합칩니다. `Σ wᵢ / (rankᵢ + 60)`이므로 스케일이 달라도 문제가 없습니다.
- **F5.** 같은 컬렉션에 문서가 3배로 쌓여 **같은 문장이 검색 결과 상위에 중복으로** 나옵니다. 한 번 저장한 뒤에는 `Chroma(persist_directory=..., embedding_function=..., collection_name=...)`로 **불러오기만** 합니다.

### G
- **G1.** 예시
  - 이미지: brain 폴더 → `flow_from_directory(batch=160)` → **(160, 150, 150, 1)** / fashion: `(60000,28,28)` → reshape → **(60000, 28, 28, 1)**
  - 시계열: jena CSV `(420551,14)` → 열 분리·슬라이싱 → split → **(420120, 144, 13)**, y **(420120, 144)**
  - 텍스트: reuters 가변 길이 list → `pad_sequences(maxlen=50)` → **(8982, 50)** → Embedding 후 **(8982, 50, 500)**
- **G2.** `weights`는 **가중치 텐서 개수**(kernel, bias, BN gamma/beta/moving_mean/moving_var 등)이고, `count_params()`는 **스칼라 파라미터 총개수**입니다. BN의 moving_mean/variance는 역전파로 학습하지 않는 **non-trainable** 통계값이라서 `trainable=True`여도 trainable_weights에서 빠집니다.
