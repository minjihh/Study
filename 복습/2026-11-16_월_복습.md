### 1-1. `map` / `lambda`
| 코드 | 의미 |
|---|---|
| `lambda x: x*2` | 이름 없는 한 줄 함수 = `def f(x): return x*2` |
| `lambda x, y: x + y` | 인자 여러 개 가능 |
| `lambda x: "합격" if x >= 60 else "불합격"` | 조건 표현식(삼항)도 가능 (단, `elif`는 불가) |

| `list(map(...))` | 실제 값으로 꺼내기. **한 번 꺼내면 소진됨** |

### 1-2. Softmax (`keras78_09_softmax.py`)
- `softmax(x) = exp(x) / sum(exp(x))` → 합이 1인 확률분포.
- x = [1, 2, 3, 4] → **[0.0321, 0.0871, 0.2369, 0.6439]**
  - 입력 4는 3보다 1 큰 값이지만 확률은 약 **2.7배(e배)** → exp가 차이를 키워 줍니다.
- `plt.pie(ratio, labels, ...)`의 **두 번째 위치 인자는 `labels`가 아니라 `explode`**입니다. 그래서 수업 코드에서는 y값이 조각을 띄우는 거리로 쓰였습니다.
  (Matplotlib 3.10부터 경고가 나오고, 3.12부터는 키워드로만 넘길 수 있습니다 → `plt.pie(ratio, labels=..., ...)`로 써야 합니다.)

### 1-3. 경사하강법 (`keras78_gradient1/2.py`)
- f(x) = x² − 4x + 6, f'(x) = 2x − 4 → 최솟값은 **(2, 2)** (gradient1의 빨간 점)
- 갱신식: `x = x − lr * f'(x)`
- lr = 0.1이면 x_new = x − 0.1(2x − 4) = **0.8x + 0.4** → (x − 2)가 매번 0.8배로 줄어듭니다.
  - 0회: 100 → 1회: **80.4** → … → 50회: **2.0014** (≈ 2 + 98 × 0.8⁵⁰)
- lr에 따른 움직임 (이 함수 기준):

| lr | x_new | 결과 |
|---|---|---|
| 0.1 | 0.8x + 0.4 | 천천히 수렴 |
| 0.5 | **2** | 한 번에 최솟값 도착 |
| 1.0 | −x + 4 | 100 ↔ −96 진동, 수렴 안 함 |
| > 1.0 | — | 발산 |

### 1-4. 학습률 실험 (`keras79_lr.py`)
- 예측 `x * w`, 목표 y = 10, x = 10 → 정답은 **w = 1**
- 미분 없이 w를 `+lr`, `−lr`로 각각 움직여 보고 loss가 작은 쪽을 고릅니다 (손으로 하는 경사하강).
- w = 0.001에서 출발해 0.001씩 움직이므로 1까지 약 **999번** 걸리고, 1000 epoch 후 w ≈ **0.999**입니다.
- ⚠️ `print`에서 `round(loss, 4) + 100`처럼 **100을 더해서 출력**합니다. 실제 loss보다 100 크게 보입니다.
  (첫 줄 실제 loss = (0.01 − 10)² = 99.8001 → 출력은 199.8001)

### 1-5. TensorBoard (`keras80_Tensorboard.py`)

|---|---|---|

### 1-6. HalvingGridSearchCV (`m10_HalvingGridSearchCV_00.py`)
- 아이디어: **후보는 많고 데이터는 적게** 시작 → 매 단계 후보를 `1/factor`로 줄이고, 데이터(resource)는 `×factor`로 늘림.
- 수업 설정: 후보 42개, `min_resources=100`, `max_resources=1437`, `factor=2`, cv=5
  (sklearn으로 같은 설정을 직접 돌려 확인했습니다)

| iter | n_candidates | n_resources | fit 횟수 (×5 fold) |
|---|---|---|---|
| 0 | 42 | 100 | 210 |
| 1 | 21 | 200 | 105 |
| 2 | 11 | 400 | 55 |
| 3 | 6 | 800 | 30 |
| **합** | | | **400** (+ refit 1) |

  - 필요한 단계 수 = 1 + ⌊log₂ 42⌋ = **6**, 실제로 가능한 단계 수 = 1 + ⌊log₂(1437/100)⌋ = **4** → 4단계에서 멈춥니다.
  - 그래서 **마지막 단계에서도 후보가 6개 남고, 데이터는 1437개가 아니라 800개만 씁니다.**
    (`aggressive_elimination=True`로 하면 앞 단계에서 후보를 더 줄여서 이 상황을 보완합니다.)
  - 비교: GridSearchCV는 42 × 5 = **210 fit을 전부 1437개 데이터로** 수행합니다.
- import: 공식 방법은
  ```python
  from sklearn.experimental import enable_halving_search_cv  # 반드시 먼저
  from sklearn.model_selection import HalvingGridSearchCV
  ```
  수업 코드의 `sklearn.model_selection._search_successive_halving`은 `_`로 시작하는 **내부(private) 모듈**이라 버전이 바뀌면 깨질 수 있습니다.

**C1.** f'(100) = 2·100 − 4 = 196 → x = 100 − 0.1 × 196 = **80.4**

**C2.** f'(100) = 196 → x = 100 − 0.5 × 196 = **2**. 이 2차함수에서는 lr = 0.5가 딱 한 번에 최솟값으로 가는 값입니다(x_new = x − 0.5(2x−4) = 2).

### 📝 오늘 기억할 3가지
1. **lr은 진동/수렴을 결정합니다**: 너무 작으면 느리고, 너무 크면 진동·발산합니다 (C3, D3).
2. **Conv2D 출력 = 입력 − 커널 + 1** (valid, stride 1). 주석을 믿지 말고 `model.summary()`로 확인하세요 (E1).
3. **Halving은 "후보 ÷ factor, 데이터 × factor"**. 가능한 단계 수가 모자라면 후보가 여러 개 남은 채로 끝납니다 (F3).
