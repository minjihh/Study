# Part B. 레포 전체 복습

## B-1. 딥러닝 기초 (keras01 ~ keras26)
- 학습 4단계: `1.데이터 → 2.모델구성 → 3.컴파일/훈련 → 4.평가/예측`
- 회귀: 출력층 `Dense(1)`, loss `mse`, 평가 R2/RMSE. 이진분류: 출력 `sigmoid` + `binary_crossentropy`. 다중분류: 출력 `softmax`(클래스 수) + `categorical_crossentropy`(y는 원핫: `pd.get_dummies`, `OneHotEncoder`, `to_categorical`) → 평가 시 `np.argmax`로 되돌림.
- 데이터 분리: train / validation / test. `validation_split` 또는 `validation_data=(x_val,y_val)`.
- 과적합(overfit) 확인: `hist.history['loss']`, `['val_loss']` 그래프. 
- `EarlyStopping(monitor='val_loss', mode='min', patience, restore_best_weights)` : mode는 loss→min, acc→max(auto 가능). `restore_best_weights` 기본값 False.
- `model.summary()` : 파라미터 수 = (입력 노드 + 1(bias)) × 출력 노드. `input_dim`(1차원 입력) vs `input_shape`.
- `batch_size`, `epochs`, `verbose`, 시간측정 `time.time()`.

## B-2. 스케일링 · 저장 · 규제 (keras27 ~ keras35)
- 스케일러(MinMax, Standard, MaxAbs, Robust): **x_train에만 `fit`**, test는 `transform`만 (`fit_transform`은 train 전용). test 데이터가 0~1을 벗어날 수 있음. 스케일링은 이상치·결측치 처리 **후에**. Robust는 이상치에 강함.
- 모델 저장/로드: `model.save`, `load_model`, `save_weights`/`load_weights`(가중치만 → 모델 구조는 다시 정의 필요).
- `ModelCheckpoint(save_best_only=True, filepath=...)` : val_loss가 개선될 때만 저장. 파일명에 `{epoch:04d}-{val_loss:.4f}` 포맷, `datetime`으로 날짜 붙임.
- `Dropout(rate)` : 학습 중에만 노드를 무작위로 끔(추론 시 적용 안 됨), 파라미터 없음, 통상 0.5 이하.
- **함수형 모델**: `Input(shape)` → `Dense(...)(앞 레이어)` → `Model(inputs, outputs)`. Sequential과 달리 분기/합치기 가능.
- GPU 세팅(`gpu세팅.txt`, `keras35_gpu_test`), conda 환경, WSL 설치 방법 등.

## B-3. CNN (keras36 ~ keras43)
- 차원 요약 (`모델종류.txt`): DNN=2차원, RNN=3차원, CNN=4차원 `(개수, 가로, 세로, 채널)`.
- `Conv2D(filters, kernel_size, input_shape=(h,w,c))` : 출력 크기 = `(입력 - 커널)/stride + 1` (padding='valid'), `padding='same'`이면 크기 유지. 28×28에 3×3 → 26×26.
- 파라미터 수 = `(커널h × 커널w × 입력채널 + 1) × filters`.
- 이미지 스케일: 0~255 → `/255.` (MinMax) 또는 `(x-127.5)/127.5` (MaxAbs 효과). 흑백은 `reshape(-1,28,28,1)`.
- `MaxPooling2D`(가장 큰 값만, 크기 축소, 파라미터 0), `GlobalAveragePooling2D`(채널별 평균 → Flatten 대체, 파라미터 감소).
- `Flatten` 후 `Dense`. 데이터셋: mnist, fashion_mnist, cifar10(32×32×3, 10종), cifar100(100종).
- CNN 아닌 DNN으로 이미지(keras41)·CNN으로 정형데이터(keras42)를 풀어 **차원 맞추기(reshape)** 연습.
- 함수형으로 CNN 구성(keras43).

## B-4. 이미지 데이터 다루기 · 증폭 (keras44 ~ keras51)
- `ImageDataGenerator(rescale, horizontal_flip, width_shift_range, rotation_range, zoom_range, shear_range, fill_mode)` + `flow_from_directory`(폴더 → 라벨 자동) / `flow(x, y)`.
- 대량 이미지 → `np.save`/`np.load`로 `.npy` 저장해 **재로딩 시간 절약** (brain, catdog, horse, rps, men_women).
- 데이터 증폭(augment): 랜덤 인덱스(`np.random.choice(..., replace=False)`)로 일부를 뽑아 변환 → 원본과 `concatenate`. **test 데이터에는 증폭 적용하지 않음**(rescale만).
- 직접 찍은 사진으로 예측(`img_to_array`, keras49 "내가 고양이상인가").

## B-5. 옵티마이저 · 학습률 (keras52 ~ 53)
- `Adam(learning_rate=...)` 기본 0.001, 학습률이 너무 크면 발산, 너무 작으면 학습이 느림.
- `ReduceLROnPlateau(monitor, patience, factor)` : val_loss가 개선 안 되면 학습률을 factor배로 감소. EarlyStopping의 patience와의 관계(Reduce가 먼저 작동하도록 보통 더 작게).

## B-6. RNN 계열 (keras54 ~ keras59)
- 시계열 → `split_x`로 `(samples, timesteps)` 로 자르고 → `reshape(samples, timesteps, features)` 3차원.
- `SimpleRNN(units)` 파라미터 = `units × (features + units + 1)`.
- `LSTM`은 RNN의 약 **4배** 파라미터(게이트 4개): `4 × units × (features + units + 1)`, `GRU`는 약 3배. 장기기억 강점·느림.
- `return_sequences=True` : 모든 timestep 출력(3차원 유지) → RNN을 여러 층 쌓을 때 필요. False(기본)이면 마지막 출력(2차원).
- `Bidirectional(SimpleRNN(...))` : 양방향 → 파라미터 2배. Wrapper 형태.
- 실습: jena 기후 데이터(keras58, 59_3).

## B-7. 자연어 / Conv1D / 앙상블 / 전이학습 (keras2 / keras60 ~ keras76)
- `Tokenizer.fit_on_texts` → `word_index`(빈도순 1부터) → `texts_to_sequences` → `pad_sequences(padding, maxlen, truncating)` 로 길이 통일 (`pre`=앞에 0).
- `Embedding(input_dim=단어사전 개수(+1), output_dim, input_length)` : 입력 2차원 → 출력 3차원, 단어를 밀집 벡터로 (원핫보다 효율적). `input_dim`은 실제 단어 수보다 크거나 같아야 함.
- reuters(다중분류), imdb(이진분류) 실습. `sparse_categorical_crossentropy`는 y를 원핫 없이 정수 라벨 그대로 사용(keras63).
- `Reshape` 레이어(keras65), `Conv1D(filters, kernel_size)` : 3차원 입력/출력, 시계열에도 유효. 뒤에 Flatten/GAP 필요 (keras67, 68).
- 앙상블(keras69): 입력이 여러 개(`x1,x2,x3`)인 모델을 각각 만든 뒤 `concatenate`/`Concatenate`로 합침. `train_test_split`에 여러 x를 한 번에 넘길 수 있음.
- `trainable` 동결(keras71): `model.trainable=False` → 학습되는 가중치 0개(`Trainable params: 0`), 가중치 불변.
- 전이학습(keras72~76): `VGG16(weights='imagenet', include_top=False, input_shape=(32,32,3))` → `include_top=False`면 분류용 Dense 제거, 입력 크기 직접 지정 가능. `model.layers[n].trainable=False`로 **부분 동결**. 여러 사전학습 모델(VGG, ResNet, DenseNet, Inception, MobileNet, EfficientNet, Xception) 비교. `model.weights` vs `model.trainable_weights` 개수 비교.

## B-8. 머신러닝 (ml/m01 ~ m08)
- m01 `feature_importances_` : 트리 계열(DecisionTree, RandomForest, GradientBoosting, XGB)의 변수 중요도(합=1), 그래프로 시각화. `gain` 기준 설명.
- m02 `KFold`+`cross_val_score` : cross_val_score가 `fit`까지 수행, 분류는 acc, 회귀는 R2. `shuffle=True, random_state` 지정.
- m03 `train_test_split` 후 **train에만 KFold** 적용, test는 마지막 평가용으로 보관. 데이터셋: iris, california, kaggle_bike, santander.
- m04~05 `all_estimators` 로 전 모델 일괄 비교(sklearn 1.9.1 기준 분류 44개), m05는 kfold 결합.
- m06~m08: Part A 참고.

## B-9. RAG (RAG/rag01 ~ rag23, RAG.txt, VectorDB.txt)
- RAG = **R**etrieval(검색, 벡터DB) + **A**ugmented(질문에 자료를 붙임) + **G**eneration(근거 기반 답변 생성).
- API 키는 코드에 직접 쓰지 않고 **환경변수 / `.env` + `load_dotenv()`** 로 관리 (`os.environ[...]`, `.strip()`으로 공백·줄바꿈 제거). 커스텀 엔드포인트는 `base_url` 함께 지정.
- LCEL: `chain = prompt | model | output_parser`, `invoke`로 실행. 출력 파서(`StrOutputParser` 등).
- 문서 파이프라인: **로드(TextLoader/PyPDFLoader) → 청킹(`RecursiveCharacterTextSplitter`: `chunk_size`, `chunk_overlap`(chunk_size보다 작아야 함), `separators`) → 임베딩(`text-embedding-3-small` 1536차원 / large 3072차원, bge-m3, Qwen3-Embedding 등) → 벡터DB 저장 → 검색 → LLM 답변**.
- Chroma: 문서+메타데이터+임베딩을 함께 관리(collection), `persist_directory` 저장/로드, 같은 코드를 반복 실행하면 sqlite에 **중복 누적**. FAISS: 벡터 검색에 특화·대용량에서 빠름, 원문 보관은 별도(`InMemoryDocstore`), `IndexFlatL2`(유클리드 거리), 저장/로드(`.faiss`+`.pkl`).
- Gradio로 챗봇 UI, 대화 history, 프롬프트 템플릿, 유사도 점수 확인.
- 검색 방식: **BM25**(키워드 기반) / **벡터검색**(의미 기반) / **하이브리드(앙상블)** = 둘을 가중 결합.

## B-10. LangGraph (LG/lg01 ~ lg09)
- `TypedDict` : 키·타입을 명시한 딕셔너리(타입힌트, 강제성은 없음).
- 그래프 구축 순서: **State 정의 → Node 정의(함수) → `StateGraph(State)` + `add_node` → `add_edge`(START/END) → `compile()` → `invoke`**.
- `Annotated[list, add_messages]` : 리듀서. 노드가 반환한 messages를 **덮어쓰지 않고 누적**.
- 도구 호출: `llm.bind_tools(tools)`, `ToolNode`, `tools_condition`(도구 호출 필요 여부로 분기), Tavily 웹 검색 / DuckDuckGo(lg06).
- 메모리(lg08): 체크포인터로 대화 상태 유지 (thread 단위).
- 병렬 실행·병합(lg09): `START`에서 두 노드로 edge → 둘 다 완료 후 `merge` 노드 실행. 각 노드는 서로 **다른 키**를 갱신해야 충돌이 없고, 같은 키를 갱신하려면 리듀서(예: concat)가 필요(lg09_2).

- **B19.** `concatenate([output1, output2, output3])` (함수) / `Concatenate()([output1, output2, output3])` (클래스, 객체 생성 후 호출). 기능은 동일.
- **B20.** 폴드마다 train/val을 나눠 `fit` → 예측 → 점수 계산을 반복하고 점수 배열을 돌려준다(분류 acc, 회귀 R2). **따로 `fit`할 필요 없음** (내부에서 복제 모델로 수행).
- **B21.** CV에 test를 쓰면 평가 데이터가 학습/선택에 관여해 낙관적 성능이 나옴. test는 최종 평가에만 사용.
- **B22.** 합은 1. 회귀의 `score`는 **R2**, 분류는 accuracy.
- **B23.** Retrieval(검색) + Augmented(검색 결과를 질문에 붙여 보강) + Generation(근거 기반 생성). 학습 데이터에 없는 최신/사내 문서도 근거로 답할 수 있고 환각(hallucination)을 줄인다.
- **B24.** 청크 경계에서 문맥이 잘리는 것을 방지하기 위해 일부 중복. overlap이 chunk_size보다 크거나 같으면 에러(또는 무의미) → 반드시 작아야 함.
- **B25.** Chroma: 벡터 + **원문 문서 + 메타데이터**를 collection으로 같이 관리, 추가·수정·삭제·필터링이 편함 → 문서/메타데이터/필터가 필요하면 우선. FAISS: **벡터 검색 속도**에 집중, 책의 "위치번호"만 빠르게 찾아주고 내용은 다른 곳(docstore)에서 관리 → 대용량에서 빠름.
- **B26.** 1536차원 (large는 3072). `len(embeddings.embed_query("hello world"))` 로 얻는다.
- **B27.** BM25: 단어 일치(키워드) 기반 점수, 벡터: 의미(임베딩 거리) 기반, 하이브리드: 둘의 결과를 가중치로 결합. 고유명사·코드명(키워드 정확 일치)과 의미 유사 질의가 섞일 때 유리 (예: "삼성전자의 반도체 사업").
- **B28.** 같은 문서가 다시 추가되어 `chroma.sqlite3`에 **중복 누적**된다 → 같은 문서가 여러 번 검색됨. (삭제 후 재생성하거나 id를 지정.)
- **B29.** 코드에 직접 쓰면 GitHub 등에 유출될 위험(**이 레포 `RAG.txt`에도 실제 키처럼 보이는 문자열이 있으니 폐기·교체하고 삭제하세요**). `.env`는 `.gitignore`에 넣어 공유되지 않게 하고 `load_dotenv()`로 환경변수에 로드. `.strip()`은 키 앞뒤의 공백·개행 제거.
- **B30.** ① State 정의 ② Node 정의 ③ `StateGraph(State)` 생성 + `add_node` ④ `add_edge`(START/END 연결) ⑤ `compile()` ⑥ `invoke()`(실행).
- **B31.** 새 메시지를 기존 리스트에 **append(누적)**하는 리듀서. 없으면 노드 반환값이 해당 키를 **덮어쓴다**(대화 기록이 사라짐).
- **B32.** `ToolNode`: LLM이 요청한 tool_calls를 실제로 실행해 결과(ToolMessage)를 state에 추가. `tools_condition`: 마지막 메시지에 tool call이 있으면 `"tools"` 노드로, 없으면 `END`로 분기하는 조건 함수.
- **B33.** `merge`로 들어오는 edge가 두 개라 두 노드 모두 완료된 슈퍼스텝 뒤에 실행. 같은 키를 동시에 갱신하면 `InvalidUpdateError`(리듀서 없는 키의 동시 업데이트) → 서로 다른 키를 쓰거나 `Annotated[list, operator.add]` 같은 리듀서(병합 함수)를 지정.
- **B34.** ① `train_test_split`에 `train_size/random_state` 미지정(재현 불가) ② `x_test`에 `fit_transform` → `transform`이어야 함 ③ test 데이터를 `validation_data`로 사용 → val 데이터를 따로 분리해야 하며, 같은 test로 평가하면 평가가 낙관적 ④ (회귀/분류 구분 없이) 컴파일 코드 누락 — `model.compile`이 `fit` 앞에 있어야 함.
- **B35.** GridSearchCV. for문은 test 점수로 최적 파라미터를 고르므로 test 과적합 위험이 있고, GridSearchCV는 train 안에서 교차검증으로 선택하며 `n_jobs` 병렬화, `best_params_`/`best_estimator_` 등 결과 접근이 편리하다. 단 조합이 많으면 시간이 매우 오래 걸린다(조합수×cv횟수) → 이후에 RandomizedSearch, 베이지안 최적화 등으로 확장.
