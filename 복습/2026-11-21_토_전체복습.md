## 2. 💾 저장하고 불러오기

### 2-1. `model.save` vs `save_weights` (`keras/keras29_1`, `29_5`, `29_6`)

| 방법 | 저장 내용 | 확장자 | 불러올 때 |
|---|---|---|---|
| `model.save(...)` | 구조 + 가중치 (+ compile 정보) | `.keras` (옛날 `.h5`) | `load_model(path)` 한 줄이면 모델 정의 **생략 가능** |
| `model.save_weights(...)` | **가중치만** | `.weights.h5` | **똑같은 구조의 모델을 먼저 만든 뒤** `model.load_weights(path)` |

- **저장하는 "시점"이 곧 저장되는 가중치**입니다.
  - `keras29_1`: 모델 정의 직후 `model.save()` → `exit()` ⇒ **훈련 전의 랜덤 초기 가중치**가 저장됨.
  - `keras29_5`: `save1.weights.h5`(훈련 전) / `save2.weights.h5`(fit 후) 두 번 저장.
  - `keras29_6`: `load_weights(save2)` 후 **fit 없이** `compile → evaluate`. `compile()`은 가중치를 초기화하지 **않기** 때문에 훈련된 성능 그대로 나옵니다.

### 2-3. 벡터DB 저장: Chroma vs FAISS (`RAG/rag17_FAISS_1_save.py`, `rag17_FAISS_2_load.py`)

| | Chroma | FAISS |
|---|---|---|
| 저장 | `from_documents(..., persist_directory=...)` 시 **자동 저장** | `db.save_local(folder_path, index_name)` **직접 호출** |
| 불러오기 | `Chroma(embedding_function, persist_directory, collection_name)` | `FAISS.load_local(folder_path, index_name, embeddings, allow_dangerous_deserialization=True)` |
| 거리 | 기본 L2 (설정 가능) | `IndexFlatL2` = **유클리드 거리** (작을수록 유사) |

- `allow_dangerous_deserialization=True`: docstore가 **pickle**로 저장되기 때문. pickle은 불러올 때 코드가 실행될 수 있으니 **내가 만든 파일만** 이 옵션으로 여세요.
- rag17_1의 함정: `faiss_db = FAISS(index=IndexFlatL2(...), docstore=InMemoryDocstore(), ...)`를 만들어 놓고, 실제로는 `db = FAISS.from_documents(...)`로 **새 인덱스를 따로** 만듭니다. → `faiss_db`는 끝까지 비어 있음(`ntotal = 0`), 사용되지 않는 준비 코드.
- `IndexFlatL2(d)`의 `d`는 **임베딩 차원**과 반드시 같아야 함. 그래서 `len(embeddings.embed_query("hello world"))`로 구함.

## 3. 🔗 합치기 — 다중 입력·다중 출력

### 3-1. 2입력 1출력 (`keras2/keras69_ensemble1.py`)
```
input1 (2,) → han1(10) → han2(20) → han3(30) → han4(5) ┐
                                                         ├ Concatenate → (8,) → mg2(10) → mg3(5) → last(1)
input21 (3,) → han21(50) → 22(40) → 23(30) → 24(20) → han25(3) ┘
```
- `train_test_split(x1, x2, y, ...)` → 넣은 순서대로 **(train, val) 쌍**이 나옴: `x1_tr, x1_val, x2_tr, x2_val, y_tr, y_val`.
- `Concatenate(name=...)([a, b])`(클래스: 만들고 → 호출) ≡ `concatenate([a, b], name=...)`(함수). 기본 `axis=-1` → 5 + 3 = **8**.
- `fit([x1, x2], y)`: 입력 순서는 `Model(inputs=[input1, input21])` 순서와 같아야 함.

### 3-2. 3입력 2출력 (`keras69_ensemble3.py`) / 1입력 2출력 (`keras69_ensemble4.py`)
- 출력이 2개면 `fit(..., [y1, y2])`, `predict` 결과는 **배열 2개짜리 리스트**.
- `evaluate` 결과 = `[전체 loss, last1_loss, last2_loss]`, 전체 = 두 loss의 **합** (기록: 38.27 + 3.08 ≈ 41.34).
- ensemble4는 `Model(inputs=input1, ...)`로 입력이 1개 → `predict(x1_pred)`만 사용, `x2_pred`·`x3_pred`는 만들어 놓고 안 씀.

### 3-3. `include_top` (`keras2/keras72_1_vgg16_include_top.py`)
- `include_top=True`(기본): Flatten + FC(4096) + FC(4096) + 1000 클래스 → 입력 **(224,224,3) 고정**, 총 138,357,544개.
- `include_top=False`: **합성곱 부분만** 남음 → 입력 크기 변경 가능(최소 32×32), 총 14,714,688개.
  - (100,100,3) → MaxPool 5번: 100→50→25→12→6→**3** ⇒ `(None, 3, 3, 512)`.
- FC 부분 파라미터 = 138,357,544 − 14,714,688 = **123,642,856** (전체의 약 89%가 FC에 몰려 있음).

### 3-4. Conv1D로 표 데이터 풀기 (`keras2/keras68_Conv1D_01_diabetes.py`)
- `(309, 10)` → `reshape(309, 10, 1)`: 특성 10개를 "길이 10, 채널 1"의 시퀀스로 봄.
- Conv1D 파라미터 = `filters × (kernel_size × 입력채널) + filters`, 출력 길이 = `L − k + 1`.
- 함정: `epochs=10`인데 `ReduceLROnPlateau(patience=20)` → **절대 발동 안 함**. `validation_split=0.5` → 309개 중 절반만 학습에 사용.

## 4. 🤝 LLM에 연결하기

### 4-1. 임베딩 차원 (`RAG/rag10_Embedding01/02`, `rag20_embedding2_bge-m3`)

| 모델 | 차원 |
|---|---|
| `text-embedding-3-small` | 1536 |
| `text-embedding-3-large` | 3072 |
| `BAAI/bge-m3` (HuggingFace, 로컬 실행) | 1024 |

- `OpenAIEmbeddings(dimensions=5)`: text-embedding-3 계열은 차원을 줄여 받을 수 있음 (저장 공간↓, 표현력↓).
- `HuggingFaceEmbeddings(model_kwargs={"device": "cpu" 또는 "cuda", "local_files_only": True})`: 처음 한 번 내려받은 뒤에는 로컬 파일만 사용.

### 4-2. retrieval chain 세트 (`RAG/rag16_챗봇놀이.py`)
```python
docu_chain = create_stuff_documents_chain(model, prompt)   # 문서들을 {context}에 "쑤셔 넣고" → prompt | model
rag_chain  = create_retrieval_chain(retriever, docu_chain)  # {input}으로 검색 → docu_chain
response = rag_chain.invoke({"input": query})
response.keys()  # dict_keys(['input', 'context', 'answer'])
```
- 프롬프트 변수 이름이 **`{context}`, `{input}`으로 정해져 있음** (`{question}`이 아님).
- `response['context']` = 검색된 `Document` 리스트, `response['answer']` = 최종 문자열.

### 4-3. 히스토리 + 유사도 임계값 + 프롬프트 (`rag21`, `rag22_1/2/3`)
- `MessagesPlaceholder(variable_name='chat_history')` 자리에 `HumanMessage`/`AIMessage` 리스트를 넣음.
- `history[-10:]` → 최근 **메시지 10개 = 질문·답변 5쌍**.
- `search_type="similarity_score_threshold"`, `score_threshold=0.7` → 관련도 점수가 0.7 미만이면 버림 → **검색 결과가 0개일 수도 있음**. 이때 22-2 프롬프트는 "주어진 정보로는 답변할 수 없습니다"라고 답하고,
- 22-3 프롬프트는 규칙을 나눠서 **인사·일상 대화 / 이전 대화로 알 수 있는 정보**는 문서 없이도 답하도록 바꿈.
- `doc.metadata.get("source")`: PDF/텍스트 로더가 붙여 준 출처(파일 경로). PDF는 `page`도 들어 있음.

### 4-4. LangGraph — 노드를 더하면 메시지가 쌓인다 (`LG/lg03_chatbot.py`, `lg04_노드엣지추가.py`)
- `State`에 `aaa`, `bbb`, `ccc`가 선언돼 있지만 invoke 때 넣지 않았고 어떤 노드도 쓰지 않음 → 결과 딕셔너리에도 없음.
- lg04 흐름: `START → prepare → chatbot → finish → END`, `add_messages` 리듀서가 **덧붙이기** 때문에 최종 메시지는
  `[0] human 질문 / [1] ai "질문을 접수했습니다." / [2] ai LLM 답변 / [3] ai "답변 처리가 완료되었습니다."`
- chatbot 노드의 LLM은 `[human, ai(접수)]` 두 개를 입력으로 받는다는 점도 기억.

### 4-5. Tool calling 루프 (`lg05_ToolNode.py`, `lg06_01_ddg.py`, `lg07_*`)
```
START → chatbot ──(tools_condition)──> tools ──> chatbot ──> ... ──> END
```
- `llm.bind_tools(tools)`: LLM에게 "이런 도구가 있다"고 알려줄 뿐, **실행은 `ToolNode`가** 함.
- `tools_condition`: 마지막 AI 메시지에 `tool_calls`가 있으면 `"tools"`, 없으면 `END` → 그래서 `add_edge('chatbot', END)`를 따로 안 씀.
- 도구를 1번 쓰면 메시지는 최소 `human → ai(tool_calls) → tool(검색 결과) → ai(최종 답)` 4개.
- Tavily(`TavilySearch`)는 결과가 **dict**(`result['results'][i]['content']`), DuckDuckGo(`DuckDuckGoSearchRun`)는 **문자열** 하나 → 그래서 lg06에서 `result['results']`를 켜면 에러.
- lg07: `graph.get_graph().draw_mermaid_png()`는 PNG **바이트** → `open(..., 'wb')`로 저장(`with`가 끝나면 자동 `close`). 07-2는 `Image.open(BytesIO(png_data))`로 파일 없이 메모리에서 열기.

### 4-6. 보너스: 불균형 이진분류 (`keras/keras22_sigmoid_santander.py`, `keras24_kaggle_santander.py`)
- y = 0: 179,902 / 1: 20,098 → **전부 0이라고 찍어도 acc ≈ 0.90**. 정확도만 보면 속기 쉬움 (그래서 Kaggle은 AUC로 평가).
- 22번: `model.evaluate(x_test, y_test)` → `x_test = test_csv`는 정답이 없는 제출용 데이터, `y_test`는 **정의된 적 없음** → `NameError`. 검증은 `x_val, y_val`로 해야 함.
- 22번 주석 "evaluate 안에는 round 처리까지 포함"은 반만 맞음: `acc` 지표만 0.5 기준으로 자르고, **loss(BCE)는 확률 그대로** 계산.
- 24번: 같은 문제를 `get_dummies` → `Dense(2, softmax)` + `categorical_crossentropy` → `argmax(axis=1)`로 풀이 (sigmoid 1개와 같은 결과를 내는 다른 방식).
