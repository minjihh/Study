## 1. 한 장 요약 (빠르게 훑기)

| 키워드 | 한 줄 정리 |
|---|---|
| `GridSearchCV` | 파라미터 **모든 조합** × cv 만큼 학습 |
| `RandomizedSearchCV` | 조합 중 **`n_iter`개만 무작위** × cv 만큼 학습 (`random_state`로 재현) |
| `parameters = [dict, dict, dict]` | dict끼리는 **따로** 조합 → 조합 수는 **곱이 아니라 합** (18+12+12=42) |
| `refit=True` | best 파라미터로 **train 전체 재학습** → `best_estimator_`, `predict`, `score` 사용 가능 |
| `best_score_` | train 내부 **CV 평균 점수** (test 점수 아님) |
| `model.score(x_test, y_test)` | 진짜 일반화 성능 확인 |
| `KerasRegressor(build_fn=...)` | Keras 모델 → sklearn 추정기로 포장 |
| `fit(..., epochs, callbacks, validation_split)` | Search의 `fit`에 넣은 인자는 **각 후보 모델의 fit에 그대로 전달** |

### 이번에 꼭 짚을 포인트 3가지
1. **조합 수 계산**
   - 한 dict 안: 각 리스트 길이의 **곱** (`2×3×3 = 18`)
   - 리스트 안 여러 dict: 각 dict 조합 수의 **합**
   - keras77 `hyperparameters`는 dict 1개 → 전부 곱: `5(batch) × 3(opt) × 4(drop) × 4(act) × 5⁵(node1~5) = 750,000` 조합 → Grid는 사실상 불가능, 그래서 **Random(n_iter=10)** 을 씀.
2. **`fit` 인자 전달 흐름 (keras77)**
   - `model.fit(x_train, y_train, epochs=100, callbacks=[es, rlr], validation_split=0.1)`
   - → RandomizedSearchCV가 각 fold마다 `KerasRegressor.fit(...)`에 같은 인자를 넘김
   - → 각 fold의 train 부분에서 다시 10%를 validation으로 떼어 EarlyStopping/ReduceLROnPlateau가 `val_loss`를 감시.
   - `batch_size`는 탐색 dict에 있으므로 후보마다 다르게 들어감.
3. **회귀에서의 `score` 의미**
   - XGBRegressor(sklearn 회귀 모델)의 `score` → **R²** (1에 가까울수록 좋음)
   - 구버전 `KerasRegressor.score` → **loss의 음수(-MSE)** (0에 가까울수록 좋음). sklearn Search는 "클수록 좋다"를 가정하므로 loss에 마이너스를 붙임.

## 3. 정답 및 해설

1. **51번** — 10(n_iter) × 5(fold) = 50 + refit 1번.
2. 조합(42)보다 `n_iter`(50)가 크면 sklearn이 경고(`UserWarning: The total space of parameters 42 is smaller than n_iter=50`)를 내고 **42개 전부**를 탐색 → 사실상 GridSearch와 같아짐. (dict 리스트에 연속분포가 없을 때)
3. **750,000개** (5×3×4×4×5⁵). Grid로 cv=3이면 225만 번 학습 → 불가능. 그래서 Random으로 일부만 샘플링.
4. 후보 10 × fold 3 = 30번 + refit 1번 = 31번 학습, 각각 최대 100 epoch → **최대 3,100 epoch**. 실제로는 EarlyStopping 때문에 더 적음.
5. 구버전 `KerasRegressor.score`는 **loss(MSE)에 마이너스**를 붙여 반환 → "클수록 좋다"는 sklearn 규칙에 맞추기 위함. 0에 가까울수록 좋은 모델.
6. `best_estimator_` → best 파라미터가 들어간 **모델 객체 전체**(XGBClassifier(...) 형태). `best_params_` → best 파라미터만 담긴 **dict** (예: `{'max_depth': 6, 'learning_rate': 0.1}`).
7. **③** — 두 번째 dict에는 `n_estimators`가 없음.
8. dict에 없는 파라미터는 **모델 기본값** 사용 (XGB 기본 `n_estimators=100`, `max_depth`는 버전 기본값(보통 6)).
9. **②**
10. `refit=False`면 최종 모델을 재학습하지 않아 `predict`/`score`/`best_estimator_` 사용 불가 → 에러. `refit=True`로 바꾸거나, `best_params_`로 모델을 새로 만들어 직접 `fit` 후 `predict`.
11. 둘 다 문제. ① `stratify=y` — 연속형 타깃은 계층 분할 불가 → 제거. ② `StratifiedKFold` — 회귀 타깃 불가(`Supported target types are: binary, multiclass`) → `KFold`로 교체.
12. 예시:
    ```python
    from tensorflow.keras.optimizers import Adam, RMSprop, Adadelta
    def build_model(..., optimizer='adam', lr=0.001):
        ...
        opt = {'adam': Adam, 'rmsprop': RMSprop, 'adadelta': Adadelta}[optimizer](learning_rate=lr)
        model.compile(optimizer=opt, loss='mse', metrics=['mae'])
    # 그리고 create_heyperparameter()의 dict에 'lr': [0.1, 0.01, 0.001] 추가
    ```
13. `pip install scikeras` 후 `from scikeras.wrappers import KerasRegressor` 사용. (scikeras는 `build_fn` 대신 `model=build_model`을 쓰고, 탐색할 모델 인자 이름 앞에 `model__`을 붙여야 함. 예: `'model__drop'`)
14. `best_score_`는 **train 데이터 내부의 CV 평균** 점수. 파라미터를 그 점수에 맞춰 골랐으므로 낙관적으로 편향(과적합)될 수 있고, 한 번도 보지 않은 test에서의 성능은 `model.score(x_test, y_test)`로 따로 확인해야 함.
15. ① 조합 수가 너무 많을 때(keras77처럼 75만 개) ② 학습 1회가 오래 걸려 시간 예산이 정해져 있을 때. (+ 중요한 파라미터가 소수일 때 Random이 더 다양한 값을 시도해 효율적)
