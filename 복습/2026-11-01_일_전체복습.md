## 1. 핵심 정리

### 1-1. Keras 기초 (keras01~35)
- **학습 흐름**: `#1 데이터 → #2 모델구성 → #3 컴파일/훈련 → #4 평가/예측`
- `train_test_split` 후 val 데이터를 한 번 더 분리 (train 0.7 / val 0.15 / test 0.15) 또는 `validation_split` 사용.
- **스케일러**: MinMax, Standard, MaxAbs, Robust(이상치에 강함). **`fit_transform`은 train에만, test는 `transform`만** (데이터 누수 방지).
- **콜백**
  - `EarlyStopping(monitor='val_loss', patience, restore_best_weights=True)` → 과적합 전에 멈춤
  - `ModelCheckpoint(save_best_only=True, filepath=...)` → 최적 모델 저장
  - `ReduceLROnPlateau` → 개선 없으면 learning rate 감소
- **저장/불러오기**: `model.save`, `load_model`, `save_weights`, `load_weights`
- **과적합 방지**: Dropout(통상 0.5 이하, **추론 시에는 적용 안 됨**), EarlyStopping
- **함수형 모델**: `Input → Dense(...)(이전층) → Model(inputs, outputs)`. Sequential과 같은 구조도 표현 가능하고, 다중 입력/출력(앙상블)에 필수.
- `model.summary()` 파라미터 수 = (입력 노드 수 × 출력 노드 수) + 출력 노드 수(bias)
- 분류: 이진 = `sigmoid + binary_crossentropy`, 다중 = `softmax + categorical_crossentropy`(OneHot) 또는 `sparse_categorical_crossentropy`(정수 라벨)

### 1-2. CNN / 이미지 (keras36~53)
- 이미지 입력 shape: `(데이터 수, 가로, 세로, 채널)`, 모델에는 `input_shape=(28, 28, 1)`
- mnist는 0~255 값 → `/255.`(MinMax)와 MaxAbs 결과가 사실상 동일
- `Conv2D` → `MaxPooling2D` → `Flatten` → `Dense`. GAP(`GlobalAveragePooling2D`)는 Flatten 대체.
- `padding='same'`, `strides`로 출력 크기 조절
- `ImageDataGenerator`: 증폭(augment), `flow`, `flow_from_directory`. 증폭 데이터는 **train에만**.
- 큰 이미지는 `np.save/np.load`(.npy)로 저장해 재사용
- Optimizer 비교(Adam 등), `ReduceLROnPlateau`

### 1-3. 모델/레이어별 차원 정리 (`모델종류.txt`)
| | DNN | CNN | RNN | Embedding |
|---|---|---|---|---|
| x shape 차원 | 2 이상 | 4 | 3 | 2 |
| input_shape 길이 | 1 | 3 | 2 | 1 |
| output 차원 | 2 이상 | 4 | 2 | 3 |

- `return_sequences=True`면 RNN 출력이 3차원 → 다음 RNN/Conv1D에 연결 가능
- `Embedding(단어사전 개수, output_dim)`: 입력 2차원 → 출력 3차원

### 1-4. RNN / NLP / 전이학습 (keras54~76)
- RNN/LSTM 입력은 `(samples, timesteps, features)`. `split` 함수로 시계열을 timesteps 단위로 자름.
- Bidirectional, Conv1D, Reshape, 앙상블(다중 입력 `Concatenate`), 상관관계(correlation)
- `Tokenizer` → `pad_sequences` → `Embedding` → LSTM/Dense
- **전이학습**: `VGG16(include_top=False)`, `trainable=False`로 일부/전체 동결, `model.layers`·`trainable_weights` 확인

### 1-5. 머신러닝 `ml/m01_feature_importances` (최신)
- 모델: `DecisionTree`, `RandomForest`, `GradientBoosting`, `XGBoost` — 모두 `feature_importances_` 제공
- 분류는 `stratify=y`로 클래스 비율 유지 (**회귀에서는 쓰면 안 됨**)
- `model.score()` → 분류는 **accuracy**, 회귀는 **R²**
- XGBoost 중요도 두 종류
  - **F-score(weight)**: 해당 feature가 split에 쓰인 *빈도*
  - **Gain**: 해당 feature로 split했을 때 *손실함수 개선량* (실질적 성능 기여) → 높을수록 중요
  - `model.get_booster().get_score(importance_type='gain')`, `plot_importance(model, importance_type='gain')`

### 1-6. LangGraph (LG/)
- **State** = `TypedDict`. `Annotated[list, add_messages]` → messages를 **덮어쓰지 않고 누적**(reducer)
- 그래프 5단계: State 정의 → Node 정의 → `StateGraph` 생성 + `add_node` → `add_edge`(START/END) → `compile()` → `invoke`
- 노드는 `state`를 받아 **바뀐 키만 dict로 반환**
- **Tool Calling**: `TavilySearch` → `llm.bind_tools(tools)` → `ToolNode(tools)` + `add_conditional_edges('chatbot', tools_condition)` → `tools → chatbot` 엣지로 루프. tool_calls가 없으면 자동으로 END.
- **Memory**: `InMemorySaver` → `compile(checkpointer=memory)`, 호출 시 `config={"configurable": {"thread_id": "user01"}}` — **같은 thread_id면 대화 기억 유지**
- **병렬 실행 / 병합 (lg09)**: START에서 두 노드로 엣지 2개 → 두 노드 모두 끝난 뒤 `merge` 노드 실행. 병렬 노드는 서로 **다른 State 키**에 써야 충돌 없음. 3번 버전은 merge에서 LLM 프롬프트로 검색결과 + 분석결과를 종합.
- 공통: `.env` + `load_dotenv()`, `os.environ[...].strip()`, `ChatOpenAI(base_url=...)`

### 1-7. RAG (RAG/)
- **RAG = Retrieval(검색) + Augmented(보강) + Generation(생성)**: 질문에 검색한 자료를 붙여 근거 기반 답변
- LCEL: `chain = prompt | model` (`|`가 연산자 오버라이드), `chain.invoke({...})`
- 파이프라인: 로더(`TextLoader`, `PyPDFLoader`) → `RecursiveCharacterTextSplitter(chunk_size, chunk_overlap)` (**overlap < size**) → 임베딩 → 벡터DB → retriever → LLM
- 임베딩: `text-embedding-3-small` = 1536차원, `-large` = 3072차원. 로컬 모델 `BAAI/bge-m3`, `Qwen3-Embedding` (HuggingFaceEmbeddings)
- **Chroma**: 문서+메타데이터+필터 함께 관리, `persist_directory`, `collection_name`, 반복 실행 시 **sqlite에 누적**
- **FAISS**: 벡터 검색에 특화(L2 거리 `IndexFlatL2`), 문서 보관은 `InMemoryDocstore`가 담당, `save_local/load_local`
- **BM25**: 키워드 기반 검색. **벡터 검색**: 의미 기반. **하이브리드(Ensemble)**: 둘을 가중 결합 → 성격이 다른 retriever를 합칠 때 효과적
- Gradio로 챗봇 UI, 대화 history, 유사도 확인, 프롬프트 커스터마이징

### 1-8. 환경/기타
- `wsl.txt`: `wsl --install -d Ubuntu-24.04 --name <이름>`, `wsl -l -v`(설치 목록), `wsl -l -o`(설치 가능 목록), `explorer.exe .`(현재 경로를 탐색기로)
- `.env` / 환경변수로 API 키 관리, `gpu세팅.txt`, `miniconda설치.txt`

## 3. 정답 및 해설

1. test 정보가 scaling 기준에 섞이면 데이터 누수. train의 min/max(평균/분산)로만 변환해야 실제 추론 환경과 같음.
2. 훈련이 멈춘 시점이 아니라 **val_loss가 가장 좋았던 epoch의 가중치**로 복원.
3. **학습 시에만** 적용, 추론에는 적용 안 함. 통상 0.5 이하.
4. `4×3 + 3 = 15`
5. 이진: `sigmoid` + `binary_crossentropy` / 정수 라벨 다중: `softmax(클래스 수)` + `sparse_categorical_crossentropy` / OneHot 다중: `softmax` + `categorical_crossentropy`
6. `x.reshape(-1, 28, 28, 1)` → `(60000, 28, 28, 1)`, `input_shape=(28, 28, 1)`
7. 3차원 `(samples, timesteps, features)`. `return_sequences=True`면 출력 **3차원**(False면 2차원).
8. 입력 2차원 `(samples, 단어 수)` → 출력 3차원 `(samples, 단어 수, output_dim)`
9. `include_top=False`: 분류용 Dense(FC) 부분을 제외하고 특징 추출부만 사용 → 내 데이터에 맞는 출력층을 직접 붙임. `trainable=False`: 해당 가중치를 **동결**하여 학습 안 함.
10. 클래스 비율을 train/test에 동일하게 유지하기 위함. 회귀는 연속값이라 클래스(범주)가 없어 사용 불가.
11. 분류 = accuracy, 회귀 = R².
12. F-score = feature가 split에 사용된 **빈도**. Gain = split으로 인한 **손실함수 개선량**. 실질 기여도는 Gain이 더 적절.
13. `model.get_booster().get_score(importance_type='gain')`
14. messages를 덮어쓰지 않고 **리스트에 누적(append/merge by id)** 하는 reducer. 없으면 노드가 반환할 때마다 이전 messages가 덮어써짐.
15. 마지막 AI 메시지에 `tool_calls`가 있으면 `tools`, 없으면 `END`. `tools → chatbot`은 도구 실행 결과를 LLM이 받아 최종 답변을 만들게 하기 위함(루프).
16. ① `compile(checkpointer=InMemorySaver())` ② `invoke(..., config={"configurable": {"thread_id": "user01"}})` — **동일 thread_id** 사용.
17. 병렬: `add_edge(START, "search")`, `add_edge(START, "analysis")`. 병합: `add_edge("search", "merge")`, `add_edge("analysis", "merge")`, `add_edge("merge", END)` — merge는 두 입력이 모두 끝나면 실행됨.
18. `state["serach_result"]` → **`state["search_result"]`** (KeyError). `[웬 검색 결과]`도 `[웹 검색 결과]`가 맞는 표기.
19. `[0]` = `human`, `[1]` = `ai`
20. Retrieval: 벡터DB에서 관련 문서 검색 / Augmented: 질문에 검색한 자료를 붙여 보강 / Generation: 그 근거로 답변 생성.
21. 청크 경계에서 문맥이 끊기는 것을 막기 위해. **`chunk_overlap < chunk_size`** 여야 함.
22. 1536차원. `len(embeddings.embed_query("hello world"))`로 동적으로 구하거나 `1536`을 직접 입력. (이후 `faiss_index.d`로 확인)
23. Chroma = 책 내용(원문)·메타데이터·필터까지 함께 관리하는 도서관. FAISS = 책 위치 번호를 매우 빠르게 찾아주는 검색기(내용 보관은 다른 시스템). **문서/메타데이터/필터를 함께 관리**해야 하면 Chroma 우선.
24. 문서가 **중복 누적**되어 sqlite에 계속 쌓임 (중복 검색 결과의 원인).
25. BM25 = 키워드(단어 일치) 기반, 벡터 = 의미 유사도 기반. 하이브리드(`EnsembleRetriever`) = 둘의 가중 결합으로 키워드 정확도와 의미 검색의 장점을 함께 얻음.
26. `embedding_fundction` → **`embedding_function`**, `search_kwardgs` → **`search_kwargs`**
27. 설치 가능: `wsl -l -o`, 설치됨: `wsl -l -v`
28. `.env` + `load_dotenv()`, 또는 OS 환경변수. 레포(git 이력 포함)에 올라간 키는 공개/유출 위험이 있고 도용·과금 피해로 이어지므로 폐기·재발급 필요.
