### 1-2. KFold 기본
```python
kfold = KFold(n_splits=5, shuffle=True, random_state=333)
scores = cross_val_score(model, x, y, cv=kfold)   # fit + score를 5번 자동 반복
print(scores, np.mean(scores))
```
- 데이터를 5조각으로 나눠 **1조각은 검증, 4조각은 훈련**을 5번 돌림 → 점수 5개.
- 모든 데이터가 **딱 한 번씩** 검증용으로 쓰임 → 데이터를 버리지 않고 평가가 안정적.
- iris 120개(train)에 5-Fold → 매번 **훈련 96개 / 검증 24개**.
- `cross_val_score`는 **컴파일·fit을 대신 해줌** (주석: "cross_val_score가 model.fit까지 시킴").
- 반환 점수의 기본값: **분류 모델 → accuracy, 회귀 모델 → R²** (모델의 `.score()` 를 사용).
  → `m02_kfold_01_california.py`에서 `print('acc : ', ...)`라고 찍었지만 실제 값은 **R²** 예요.

### 1-3. `shuffle=True`가 중요한 이유 (실행 확인)
iris는 라벨이 `0,0,…,1,1,…,2,2` 순서로 **정렬**되어 있어요. `KFold(5)`(shuffle 없음)로 자르면 검증 조각의 클래스 분포가:
```
[30 0 0]  [20 10 0]  [0 30 0]  [0 10 20]  [0 0 30]
```
→ 1번 조각은 전부 0번 클래스인데, 훈련 데이터엔 0번 클래스가 하나도 없음 → 정답률 0점 가능!
그래서 코드에서 항상 `shuffle=True, random_state=333`을 같이 씀.

### 1-4. `cross_val_score` vs `cross_val_predict`
| | `cross_val_score` | `cross_val_predict` |
|---|---|---|
| 반환 | fold별 **점수** 배열 (길이 = n_splits) | 각 샘플의 **예측값** 배열 (길이 = 데이터 개수) |
| 사용처 | 모델 성능 비교 | 예측값으로 직접 지표 계산 (`accuracy_score`, `r2_score`) |

⚠️ **주의 (m03 코드에 있는 개념적 문제):**
```python
y_predict = cross_val_predict(model, x_test, y_test, cv=kfold)
```
이 줄은 **test 데이터를 5조각으로 나눠 그중 4조각(24개)으로 또 훈련**하고 1조각(6개)을 예측하는 걸 반복해요.
즉 ① train으로 학습한 모델로 test를 예측하는 게 **아니고**, ② test의 정답(`y_test`)을 훈련에 써버립니다.
"train에서 학습 → test로 평가"를 하려면 이렇게 쓰는 게 맞아요:
```python
model.fit(x_train, y_train)
y_predict = model.predict(x_test)
accuracy_score(y_test, y_predict)
```
(그리고 `cross_val_score`는 내부에서 모델을 **복사(clone)** 해서 훈련하기 때문에, 호출이 끝나도 원래 `model`은 **훈련 안 된 상태**입니다. 실행해 보면 `hasattr(model, 'tree_') == False`.)

### 1-5. 스케일링 순서 (m03)
```python
x_train = scaler.fit_transform(x_train)   # train으로 기준(평균/표준편차) 만들고 변환
x_test  = scaler.transform(x_test)        # test는 그 기준으로 변환만
```
- test에 `fit`하면 test 정보가 새어 들어감(데이터 누수).
- 참고: DecisionTree·RandomForest·XGB 같은 **트리 모델은 스케일링 영향이 거의 없음** (값의 크기가 아니라 순서로 분기하기 때문).

### 1-6. `stratify=y` 와 불균형 데이터 (santander)
- santander: `0 → 179,902개`, `1 → 20,098개` (약 9:1 불균형).
- `train_test_split(..., stratify=y)` → train/test 모두 9:1 비율 유지.
- 하지만 코드의 `KFold`는 **stratify 기능이 없음** → 불균형 데이터에선 `StratifiedKFold`가 더 적합.
- 정확도 0.9082가 높아 보여도, **전부 0이라고 찍어도 약 0.90**이 나오는 데이터예요. 불균형일 땐 F1 / AUC 등도 같이 봐야 함.

### 1-7. `all_estimators`
```python
all = all_estimators(type_filter='classifier')   # [('AdaBoostClassifier', <class>), ...]
for name, model in all:
    try:
        model = model()            # 클래스 → 인스턴스 (괄호!)
        model.fit(x_train, y_train)
        print(name, model.score(x_test, y_test))
    except:
        print(name, '모델 오류')
```
- 반환값은 **(이름 문자열, 모델 클래스)** 튜플의 리스트 → for문에서 언패킹.
- `model()`을 **try 안에서** 해야 하는 이유: `estimator=`처럼 필수 인자가 있는 모델(예: `VotingClassifier`, `StackingClassifier`)은 인스턴스 생성부터 오류가 나기 때문.
- `all`이라는 변수명은 파이썬 내장 함수 `all()`을 덮어씀 → 동작은 하지만 `all_models` 같은 이름이 더 안전.
- `except:` 만 쓰면 어떤 오류인지 안 보임 → `except Exception as e: print(name, e)`로 바꾸면 디버깅이 쉬움.

### 1-8. `m05_all_estimators2_kfold.py`에서 눈여겨볼 점
- **iris(분류 데이터)**에 `type_filter='regressor'`(회귀 모델)를 적용 → 실행은 되지만, 회귀 모델이 0~2 사이 **실수**를 예측하고 R²로 평가하는 것이라 분류 문제로는 의미가 약함. 회귀 실습이라면 `fetch_california_housing` 등을 쓰는 게 맞아요.
- `n_split`, `kfold`를 for문 **안에서** 매번 새로 만드는데, 한 번만 만들어도 됨 (밖으로 빼기).
- 주석의 "모델의 개수: 44"는 classifier 기준 값 → regressor 개수는 다름.
