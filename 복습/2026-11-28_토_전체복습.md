## 1. 이미지 증폭: `ImageDataGenerator` (keras44 ~ keras51)

### 1-1. 기본 구조 (`keras44_ImageDataGenerator1.py`)
```python
train_datagen = ImageDataGenerator(rescale=1./255, horizontal_flip=True, ..., fill_mode='nearest')
test_datagen  = ImageDataGenerator(rescale=1./255)   # test는 스케일링만!
xy_train = train_datagen.flow_from_directory(path_train, target_size=(100,100),
              batch_size=10, class_mode='binary', color_mode='grayscale', shuffle=True)
```
- **train에만 증폭을 쓰고 test는 rescale만 해.** test는 "실제 들어올 데이터"처럼 둬야 하거든.
- `flow_from_directory`는 **폴더 이름(알파벳순)**으로 라벨을 붙여. 예를 들어 `ad/`는 0, `normal/`은 1이 돼.
- 돌려주는 건 `DirectoryIterator`야. `xy_train[i]`는 `(x배치, y배치)` 튜플이야.
  - `xy_train[0][0].shape`는 `(10, 100, 100, 1)` (흑백이라 채널이 1)
  - `xy_train[0][1].shape`는 `(10,)` (binary). `categorical`이면 `(10, 2)`
- 160장을 batch 10으로 나누면 배치가 16개야. 인덱스는 **0~15**라서 `xy_train[16]`은 에러가 나.
- 증폭은 **배치를 꺼낼 때마다 랜덤으로 새로** 적용돼. 같은 `[0]`을 다시 꺼내도 이미지가 달라질 수 있어.
- ⚠️ `zoom_range=1.2`이면 확대 비율이 `[1-1.2, 1+1.2] = [-0.2, 2.2]` 범위가 돼서 비정상적이야. 보통은 0.1~0.2를 써.

### 1-2. 한 장을 증폭하기 (`keras50_flow1.py`)
- `load_img`로 PIL 이미지를 읽고, `img_to_array`로 `(200,200,3)`을 만든 다음, `np.expand_dims(axis=0)`로 **`(1,200,200,3)`**을 만들어.
- `flow()`는 **4차원(N, H, W, C)**만 받아. 그래서 한 장이라도 배치 축이 필요해.
- `it.next()` 대신 `next(it)`를 써야 하는 건 **Keras 버전 차이**야. 최근 Keras에서 `.next()` 메서드가 빠졌어. 주석에는 파이썬 버전 때문이라고 적혀 있는데, 실제로는 라이브러리 버전 문제야.

### 1-3. `np.tile`의 함정 (`keras50_flow2_next.py`)
```python
np.tile(x_train[0], 100).shape                    # (28, 2800)  ← 마지막 축(가로)으로 이어 붙음
np.tile(x_train[0].reshape(28*28), 100).reshape(-1,28,28,1)   # (100,28,28,1) ✅ 정상
```
- 2차원 `(28,28)`을 그대로 tile하면 **가로로** 이어 붙어. 이걸 `reshape(-1,28,28,1)` 하면 shape은 맞는데, 실제로는 **한 행이 28번 반복된 줄무늬 그림**이 돼. 그래서 imshow를 하면 그림이 이상하게 보이는 거야.
- 1차원으로 펼친 다음 tile하면 784개짜리 묶음이 순서대로 반복되니까 reshape해도 그림이 정상으로 나와.

### 1-4. 데이터 늘리기 (`keras51_augment1_fashion.py`)
흐름은 이래.
1. `np.random.choice(60000, 40000, replace=False)`로 **중복 없이** 4만 개를 뽑아.
2. `x_train[randidx].copy()`로 복사해. copy를 하는 이유는 원본을 건드리지 않으려고야.
3. 4차원으로 reshape한 다음 `datagen.flow(..., batch_size=augment_size, shuffle=False).next()[0]`로 **한 번에 전부** 변환해.
4. 원본과 `np.concatenate`로 합쳐서 `(100000,28,28,1)`을 만들어.

> 🚨 **실제 코드의 버그**
> ```python
> xy_augmented = datagen.flow(x_augmented, y_augmented, ...).next()[0]
> # 주석: "x_augmented에도 datagen이 적용되어 x_augmented로 사용해도 문제 없음"  ← ❌ 틀림
> x_train = np.concatenate((x_train, x_augmented))
> ```
> `flow()`는 입력 배열을 **제자리에서 바꾸지 않아**. 변환된 결과는 반환값인 `xy_augmented`에만 들어 있어.
> 그래서 합쳐진 `x_augmented`는 **증폭도 안 되고 rescale도 안 된 0~255 원본 복사본**이야.
> 그 결과 학습 데이터 앞쪽 6만 개는 0~1 범위, 뒤쪽 4만 개는 0~255 범위가 섞여 버려.
> 고치려면 `x_augmented = datagen.flow(...).next()[0]`처럼 반환값을 다시 받아야 해.
> `keras51_augment5_men_women_여자만.py`의 `x_train_w_augmented`에도 같은 버그가 있어.

### 1-5. 합친 다음에 섞어야 하는 이유 (`augment5`)
- `validation_split=0.2`는 **섞기 전에, 데이터의 맨 뒤 20%**를 검증용으로 떼어 가.
- 증폭 데이터를 뒤에 붙인 채로 학습하면 검증 데이터가 **전부 증폭된 데이터**가 돼. augment1에서는 뒤쪽 2만 개, augment5에서는 전부 여자 데이터야.
- 그래서 `indices = np.random.permutation(len(x_train))`로 섞는 게 맞아. augment5는 이걸 했고, augment1은 안 했어.
- `np.random.randint(n, size=8000)`은 **중복을 허용**해. 원본 여자 데이터가 8000개보다 적으면 중복이 생길 수밖에 없으니까 이 경우엔 randint가 맞아.
- augment5 중간의 `np.save(... 'keras51_gender_x.npy', arr=x)`는 증폭한 `x_train`이 아니라 **원본 `x`**를 저장해. 파일 이름만 보면 착각하기 쉬워.

## 2. 학습률과 콜백 (keras52, keras53)

- `Adam()`의 기본 학습률은 **0.001**이야. keras52에서는 `Adam(learning_rate=0.01)`로 바꿔 가며 비교했어. diabetes에서 lr 0.01일 때 RMSE가 약 56.9였어.
- `ReduceLROnPlateau(monitor='val_loss', patience=20, factor=0.5)`는 val_loss가 20 에폭 동안 개선되지 않으면 **lr에 0.5를 곱해**.

> 🚨 **콜백 patience의 순서 문제** (keras53 전체 파일 공통)
> ```python
> es  = EarlyStopping(patience=10, restore_best_weights=True)
> rlr = ReduceLROnPlateau(patience=20, factor=0.5)
> ```
> 두 콜백 모두 "개선이 없던 에폭 수"를 세. 그래서 **ES가 10에서 먼저 학습을 멈추고, RLR은 한 번도 실행되지 않아.**
> RLR이 동작하게 하려면 **RLR patience < ES patience**로 설정해야 해. 예를 들어 RLR 10, ES 30처럼.
> 게다가 `keras53_ReduceLR02_diabetes.py`는 `epochs=10`이라서 두 콜백 모두 의미가 없어.
> `validation_split=0.5`이면 train 309개 중 절반만 학습에 쓰여.

## 3. 텍스트를 숫자로: Tokenizer와 Embedding (keras60, keras61)

### 3-1. Tokenizer (`keras60_Tokenizer1.py`)
```python
token = Tokenizer(); token.fit_on_texts([text])   # 반드시 리스트로 넣기!
token.word_index   # {'마구':1, '진짜':2, '매우':3, '나는':4, ...}
token.texts_to_sequences([text])   # [[4,5,2,2,3,3,6,7,8,1,1,1,9]]
```
- 인덱스는 **빈도 높은 순서**로 붙고, 빈도가 같으면 **먼저 나온 단어**가 앞 번호를 받아. 그리고 **1부터 시작**해. 0은 패딩용으로 비워 둬.
- 리스트 없이 문자열을 그대로 넣으면 문자열을 **글자 단위**로 돌면서 학습해 버려.
- 시퀀스 길이는 토큰 13개라서 `(1, 13)`이야. 주석에 `(1,14)`로 적힌 건 틀린 거야.
- 토큰 번호는 크기에 의미가 없어. 2가 1의 두 배라는 뜻이 아니야. 그래서 원핫 인코딩이나 Embedding이 필요해.
- 원핫 3가지 방식을 비교하면 이래.
  - `pd.get_dummies`와 `OneHotEncoder`는 **실제로 나온 값(1~9)**만 열로 만들어서 9열이 돼. OneHotEncoder는 `(-1,1)`로 reshape해야 하고 `sparse_output=False`가 필요해.
  - `to_categorical`은 **0부터 최댓값까지** 열을 만들어서 10열이 돼. 0번 열은 전부 0이야. 그래서 "토크나이저 데이터에는 0이 없으니 주의"라는 주석이 붙어 있어.

### 3-2. 패딩과 Embedding (`keras61_Embedding04_중요.py`)
```python
pad_sequences(x, padding='pre', maxlen=5, truncating='post')   # → (15, 5)
```
- `padding='pre'`는 **앞쪽**을 0으로 채워. 예를 들어 `[2,3]`은 `[0,0,0,2,3]`이 돼. RNN은 마지막 시점의 정보가 중요해서 보통 pre를 써.
- `truncating`은 maxlen보다 긴 문장을 어느 쪽에서 자를지 정해. 기본값은 `'pre'`(앞부분을 자름)야.
- `Embedding(input_dim=단어사전 크기, output_dim=벡터 차원)`의 출력은 **3차원 `(None, 5, 100)`**이야. 그래서 바로 RNN이나 LSTM에 넣을 수 있어.
- 파라미터 수는 이렇게 계산해.
  - Embedding: `input_dim × output_dim` = 30×100 = **3000**
  - SimpleRNN(10): `units × (input_dim + units + 1)` = 10×(100+10+1) = **1110**
  - Dense(1): 10+1 = **11**

> 🚨 **`input_dim`이 1 모자라**
> `word_index`에 단어가 30개 있고 인덱스는 1~30이야. 여기에 패딩 0까지 더하면 값의 종류가 **31개**야.
> `Embedding(30, 100)`은 0~29만 받을 수 있어서, `'구라친다'`의 30번이 들어오면 CPU에서는 `indices ... = 30 is not in [0, 30)` 에러가 나.
> 정답은 **`input_dim = len(token.word_index) + 1 = 31`**이야. 이러면 파라미터는 3100이 돼.
> 다만 실제 파일은 패딩 직후에 `exit()`가 있어서 모델 코드까지는 실행되지 않아. 주석을 지우고 돌려 보면 에러가 날 거야.

## 4. 상관분석: 시점을 맞추는 문제 (`keras70_correlation.py`)

- 세 종목의 CSV를 `▲▼`, 쉼표를 제거해서 숫자로 바꾸고, `pd.concat(axis=1, join='inner')`로 **세 종목 모두 있는 날짜만** 합쳐.
- **같은 날 상관관계**는 예측에 쓸 수 없어. 오늘 삼성 시가를 맞히는데 오늘 하이닉스 종가를 쓰는 건 미래 정보를 쓰는 거니까.
- `shift(1)`은 **어제 피처를 오늘 행으로 내려**. 그래서 "전날 피처와 다음날 삼성 시가"의 상관을 볼 수 있어. 이게 실제 예측 상황과 같은 조건이야.
- `reindex(...abs().sort_values(ascending=False))`는 **절댓값 기준**으로 정렬해. 강한 음의 상관도 유용한 피처니까.
- 상관계수는 -1부터 1까지이고 **선형 관계만** 측정해. 상관이 높다고 인과관계가 있다는 뜻은 아니야.

`validation_split`은 섞기 전에 **맨 뒤 20%**를 떼어 가. 그래서 검증 데이터 2만 개가 **전부 증폭 데이터**가 돼. 학습 데이터에서 증폭 데이터의 비율도 의도와 달라지고, val_loss 기반의 ES와 MCP도 편향돼. 그래서 `np.random.permutation`으로 먼저 섞어야 해.
</details>

**Q6.** `np.random.choice(n, size, replace=False)`와 `np.random.randint(n, size=size)`는 어떻게 다를까? `n=4500`에서 `size=8000`을 뽑아야 한다면 어느 쪽을 써야 할까?
<details><summary>정답 보기</summary>

choice에 `replace=False`를 주면 **중복 없이** 뽑아. randint는 **중복을 허용**해. `size > n`이면 중복 없이 뽑는 게 불가능해서 `replace=False`는 ValueError가 나. 그래서 **randint**(또는 `choice(..., replace=True)`)를 써야 해.
</details>
