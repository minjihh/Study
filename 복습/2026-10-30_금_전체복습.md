## 1. 최근 추가분 (10-23) — 우선 복습

### 1-1. Feature Importance (`ml/m01_feature_importances01~04`)
- 모델 4종 비교: `DecisionTree`, `RandomForest`, `GradientBoosting`, `XGBoost` (분류는 iris, 회귀는 diabetes).
- `model.feature_importances_` 로 각 컬럼이 얼마나 기여했는지 확인. 합은 1.
- 분류 `model.score` = accuracy, 회귀 `model.score` = R².
- `stratify=y` 는 **분류에서만** 사용 (클래스 비율 유지). 회귀에서는 쓰면 안 됨.
- XGBoost의 두 가지 중요도
  - F-score(weight): 그 feature가 트리 분기에 **사용된 빈도**. (`feature_importances_` 기본값)
  - Gain: 그 feature로 분기했을 때 **손실함수가 개선된 정도**. 실질적인 성능 기여도에 가까움. `model.get_booster().get_score(importance_type='gain')`
- 그래프: `from xgboost import plot_importance` → `plot_importance(model, importance_type='gain')` 후 `plt.show()`

### 1-2. LangGraph 병렬 실행 + 병합 (`LG/lg09_*`)

### 2-2. Keras 기초 (`keras/`)
- 흐름: 데이터 → 모델 구성 → compile/fit → evaluate/predict.
- **train/test split → 그 뒤에 scaling**. scaler는 `x_train`에만 `fit`, `x_test`는 `transform`만 (test로 fit하면 데이터 누수/과적합 위험).
- 스케일러: MinMax(0~1), Standard(평균0·분산1), MaxAbs(절댓값 최대로 나눔), Robust(중앙값/IQR, 이상치에 강함). 이상치·결측치 처리 후 적용.
- 회귀: 마지막 `Dense(1)`, loss `mse`. 이진분류: `sigmoid` + `binary_crossentropy`. 다중분류: `softmax` + `categorical_crossentropy` (y를 one-hot) 또는 `sparse_categorical_crossentropy` (one-hot 불필요, 성능 차이 없음).
- 콜백: `EarlyStopping(monitor='val_loss', patience, restore_best_weights=True)`, `ModelCheckpoint`, `ReduceLROnPlateau(factor=0.5)`.
- 과적합 대응: validation, EarlyStopping, Dropout(파라미터 없음).
- 저장/불러오기: `model.save()` (.keras) / `load_model`, `save_weights` / `load_weights` (모델 구조는 직접 만들어야 함).
- 함수형 API: `Input` → `Dense(...)(x)` → `Model(inputs, outputs)`. 
- 옵티마이저: `Adam(learning_rate=...)`, keras 기본 lr = 0.001.
- 시간 측정: `time.time()`; GPU 확인: `tf.config.list_physical_devices('GPU')`.

### 2-3. CNN / 이미지 (`keras/`)
- 차원: DNN 2차원, RNN 3차원, CNN 4차원 `(데이터수, 가로, 세로, 채널)`. 모델의 `input_shape=(가로, 세로, 채널)`.
- 픽셀은 0~255 → MinMax(`/255.`)와 MaxAbs 적용 결과가 사실상 동일.
- `padding='same'`, `stride`, `MaxPooling2D` 로 크기 조절. Conv2D 파라미터 수 = (kernel_h × kernel_w × 입력채널 + 1) × 필터수.
- 데이터셋: mnist, fashion_mnist, cifar10, cifar100, 말/사람, 가위바위보, 남자/여자, 고양이/강아지.
- `ImageDataGenerator`: train은 증강(flip, shift, rotation, shear, fill_mode), **test는 rescale만**, `shuffle=False`. `flow_from_directory(class_mode='binary', color_mode=...)`.
- 큰 이미지는 `np.save/np.load` (npy)로 저장해 재사용, `img_to_array`, `flow()`로 증강 데이터 생성.
- Conv 후 Dense로 연결하려면 `Flatten()` (또는 GAP).

### 2-4. RNN / 시계열 / NLP (`keras/`, `keras2/`)
- 시계열 데이터는 `split_x`(슬라이딩 윈도우)로 자르고 `(samples, timesteps, features)` 3차원으로 reshape.
- `SimpleRNN`, `LSTM`, `GRU`, `Bidirectional`. RNN 파라미터 수 = units × (units + features + 1). time step이 늘어도 파라미터 수는 불변(같은 가중치를 재사용).
- `return_sequences=True` → 3차원 출력(다음 RNN에 연결 가능), False → 2차원(Dense에 바로 연결).
- `Conv1D`: 시계열에도 잘 동작. 3차원 입력/3차원 출력 → Dense 연결 전 `Flatten`.
- 텍스트: `Tokenizer.fit_on_texts` → `word_index`(빈도 높은 순으로 1번부터) → `texts_to_sequences` → `pad_sequences(padding, maxlen, truncating)` → `Embedding(단어사전수, output_dim)`.
- `Embedding`: 입력 2차원 → 출력 3차원. 원핫보다 효율적(번호 크기가 의미를 갖는 문제 해결).
- 데이터: reuters, imdb, jena(기후 시계열).
- `Reshape` 레이어: 순서/값은 바꾸지 않고 shape만 변경.

#### Layer별 입출력 비교
| | Dense | Conv2D | Conv1D | RNN/LSTM | Embedding |
|---|---|---|---|---|---|
| 입력 차원 | 2↑ | 4 | 3 | 3 | 2 |
| 출력 차원 | 2↑ | 4 | 3 | 2 (return_sequences=True면 3) | 3 |
| input_shape | 1 | 3 | 2 | 2 | 단어수, output_dim |

### 2-5. 앙상블 / 전이학습 (`keras2/`)
- 앙상블(다중 입력): 입력 2개 → 각각 모델 → `Concatenate()([out1, out2])` → 합쳐서 출력. `Model(inputs=[in1, in2], outputs=...)`. fit도 `[x1, x2]`로 전달. `train_test_split`은 x1, x2, y를 한 번에 분할 가능.
- 상관관계(`correlation`), 주가 맞추기 실습.
- `model.weights` vs `model.trainable_weights`: Dense 레이어 1개 = kernel + bias = 2개. 3층이면 총 6개. `model.trainable = False` 로 **동결**하면 `trainable_weights`가 0개, `weights`는 그대로.
- VGG16 전이학습: `VGG16(weights='imagenet', include_top=False, input_shape=(32,32,3))`. `include_top=False` 면 입력 크기를 바꿀 수 있고 하단 FC층(Flatten/Dense)이 사라짐 → 직접 `Flatten`+`Dense` 추가.
- 부분 동결: `model.layers[i].trainable = False`.
- `keras75`: VGG, ResNet, DenseNet, Inception, MobileNet, EfficientNet, Xception 등 여러 사전학습 모델의 가중치 수 비교.

### 2-6. LangGraph (`LG/`)
- `TypedDict`: 키와 타입을 명시한 dict 타입 힌트 (강제성은 없음).
- **State / Node / Edge** 로 구성. `StateGraph(State)` → `add_node` → `add_edge` → `compile()` → `invoke()`.
- `Annotated[list, add_messages]`: **Reducer**. 새 메시지를 덮어쓰지 않고 **append**. 단, `id`가 같으면 덮어씀.
- 노드는 `state`를 받아 **바뀐 키만** dict로 반환.
- `START`, `END` 가상 노드. 흐름 예: START → prepare → chatbot → finish → END.
- 툴 호출: `llm.bind_tools(tools)`, `ToolNode(tools)`, `add_conditional_edges('chatbot', tools_condition)` — tool_calls가 있으면 `tools` 노드로, 없으면 END. 그리고 `add_edge('tools', 'chatbot')` 으로 루프.
- 검색 툴: Tavily(`TavilySearch`), DuckDuckGo(`DuckDuckGoSearchRun`, 무료지만 불안정). 툴은 여러 개 등록 가능.
- 메모리: 그냥 `invoke`를 두 번 호출하면 기억 못 함. `compile(checkpointer=InMemorySaver())` + `config={"configurable": {"thread_id": "user01"}}` 를 **같은 thread_id** 로 넘겨야 대화가 이어짐.
- 그래프 시각화: `graph.get_graph().draw_mermaid_png()`.
- LLM 접속: `ChatOpenAI(model_name, temperature=0, api_key, base_url)` — MonoGPT 라우터는 `base_url`도 필요.

### 2-7. RAG (`RAG/`)
- **R**etrieval(검색) → **A**ugmented(질문에 자료를 붙임) → **G**eneration(근거 기반 답변 생성).
- LCEL: `chain = prompt | model | output_parser`. `PromptTemplate.from_template("{topic}...")`, `chain.invoke({"topic": ...})`. `StrOutputParser`를 붙이면 `.content` 없이 문자열이 바로 나옴. 프롬프트로 페르소나/포맷 부여 가능.
- 임베딩: 문장을 숫자 벡터로. `text-embedding-3-small` = 1536차원, `-large` = 3072차원, `dimensions=`로 조절 가능. HuggingFace `BAAI/bge-m3` = 1024차원, `Qwen3-Embedding-0.6B`도 사용.
- 파이프라인: 로드(`TextLoader`, `PyPDFLoader`) → 청킹(`RecursiveCharacterTextSplitter`: `chunk_size`, `chunk_overlap`(항상 chunk_size보다 작아야 함), `separators`) → 임베딩 → 벡터DB 저장 → `retriever` → LLM.
- **Chroma**: 문서 원문 + 메타데이터 + 임베딩을 함께 관리(collection), 추가/수정/삭제 쉬움. `Chroma.from_documents(...)`는 **저장**, 불러올 때는 `Chroma(embedding_function, persist_directory, collection_name)` (from_documents 쓰면 또 저장됨 → sqlite에 누적).
- **FAISS**: 벡터를 빠르게 찾는 데 집중(책의 위치번호). `faiss.IndexFlatL2(차원)` — 유클리드 거리. 대용량에서 빠름. docstore는 별도(`InMemoryDocstore`).
- 검색: `similarity_search(query, k=4)` (기본 k=4), `as_retriever(search_kwargs={"k": 2})`.
- 하이브리드(앙상블) 검색: **BM25**(키워드 기반) + **벡터 검색**(의미 기반) → `EnsembleRetriever(retrievers=[...], weights=[0.5, 0.5])`.
- Gradio: `gr.ChatInterface(fn=answer_invoke(message, history))` 로 챗봇 UI, history 사용.

## 4. 정답 및 해설

1. 클래스 비율을 train/test에 동일하게 유지하기 위해. 회귀의 y는 연속값이라 "클래스"가 없어서 쓸 수 없음.
2. 분류: accuracy(정확도), 회귀: R².
3. F-score(weight)는 해당 feature가 분기에 사용된 **횟수**, Gain은 해당 feature 분기로 **손실이 줄어든 정도**. 성능 기여도는 Gain이 더 적합.
4. `add_edge(START, "search")`, `add_edge(START, "analysis")` 처럼 START에서 두 노드로 각각 edge. merge는 `search→merge`, `analysis→merge` 두 edge가 있어 **둘 다 끝난 뒤** 실행.
5. `state["serach_result"]` 오타 → `KeyError`. `state["search_result"]`로 수정.
6. 1: 두 문자열을 `+`로 이어 `final_result`에 저장, 2: 구분선과 함께 concat 하여 `messages`에 assistant 메시지로 추가, 3: 두 결과를 프롬프트에 넣어 **LLM이 종합 답변** 작성. 3번은 검색(최신)과 분석(기존 지식)을 구분하며 읽기 좋은 하나의 답변으로 통합.
7. 먼저 scaling하면 test 정보가 scale 기준에 섞여 누수/과적합 위험. `x_train`만 `fit_transform`, `x_test`는 `transform`만.
8. 평균/표준편차 대신 **중앙값과 IQR**을 쓰기 때문.
9. categorical: y를 one-hot(`to_categorical`/`OneHotEncoder`)으로, sparse: 정수 라벨 그대로. 성능 차이는 없음.
10. 가장 좋았던 epoch의 가중치로 되돌림(기본값 False). patience는 개선이 없어도 기다릴 epoch 수.
11. `save`는 구조+가중치(+컴파일 정보), `save_weights`는 가중치만. `load_weights` 전에는 동일 구조의 모델을 먼저 만들고 compile 해야 함.
12. 지표(val_loss 등)가 patience 동안 개선되지 않으면 lr에 0.5를 곱해 절반으로 줄임.
13. `(28, 28, 3)` — 데이터 개수는 제외.

16. test는 평가용이므로 증강하지 않고 정규화만. 예측 순서와 라벨 순서를 맞추기 위해 shuffle 안 함.
17. 이미지 로딩·변환이 오래 걸려서, 한 번 변환한 numpy 배열을 저장해 빠르게 재사용하기 위해.
