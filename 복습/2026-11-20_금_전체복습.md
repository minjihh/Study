## 2. 🔍 오늘의 코드 정밀 읽기

### 2-1. 공백 하나 들어간 `mode` (`keras/keras20_EarlyStopping1_california.py`)
```python
es = EarlyStopping(monitor='val_loss', mode=' min', patience=10, restore_best_weights=True)
```
- `' min'`(앞에 공백) 은 `'min'`과 **다른 문자열** → Keras가 "알 수 없는 mode" 경고를 띄우고 **`'auto'`로 대체**합니다.
- `auto`는 monitor 이름으로 방향을 추측: `val_loss` → min, 이름에 `acc`가 있으면 → max. 그래서 **이 코드는 우연히 정상 동작**합니다.
- 다만 `monitor='val_r2'`처럼 "커야 좋은" 커스텀 지표라면 auto가 min으로 추측해 **반대로 동작**할 수 있으니 오타는 고치는 게 원칙.
- `epochs=500000` + EarlyStopping = "충분히 크게 주고 ES가 멈추게" 하는 패턴. 실제 학습 epoch 수는 `len(hist.history['loss'])`로 확인.

### 2-2. 스케일러 — 전체 fit vs train fit, 그리고 **빠진 x_val** (`keras27`, `keras30`)
- `keras27_Scaler01`: `scaler.fit(x)` → **전체 x로 fit** 후 split → test 정보(min/max)가 학습 전처리에 새어 들어감(**데이터 누수**).
- `keras30_ModelCheckPoint1`: `x_train = scaler.fit_transform(x_train)`, `x_test = scaler.transform(x_test)` ✅ 정석.
  - 그런데 **`x_val`은 transform을 안 했습니다.** (`validation_data=(x_val, y_val)`에 원본 그대로 들어감)
  - 결과: 모델은 스케일된 값으로 학습하는데 val_loss는 **원본 스케일 데이터**로 계산 → val_loss가 비정상적으로 크고 들쭉날쭉 → `EarlyStopping`·`ModelCheckpoint(save_best_only)`가 **엉뚱한 기준으로** 멈추고 저장합니다.
  - 고침: `x_val = scaler.transform(x_val)` 한 줄 추가.
- 스케일러 4종: MinMax `(x−min)/(max−min)` → 0~1 / Standard `(x−평균)/표준편차` / MaxAbs `x/|x|max` → −1~1 / Robust `(x−중앙값)/IQR` → 이상치에 강함.

### 2-3. 원핫 3가지 방법의 차이 (`keras/keras23_softmax1_OneHot_iris.py`)
| 방법 | 입력 shape | 특징 |
|---|---|---|
| `to_categorical(y)` | `(N,)` | **0부터 max까지** 열 생성 → y가 `[0,1,4]`면 열 5개(2,3 열은 전부 0) |
| `pd.get_dummies(y)` | `(N,)` | **실제 등장한 값만** 열 생성, 기본 dtype bool → `dtype=int` |
| `OneHotEncoder(sparse_output=False)` | **`(N,1)` 2차원 필수** | fit한 데이터의 클래스 수만큼 열 → `y.reshape(-1,1)` 후 `fit_transform` |
- `sparse_output=True`(기본)면 결과가 **희소행렬(sparse matrix)** 로 나옴 (코드 주석의 "혼동행렬"은 오기 — confusion matrix가 아니라 sparse matrix).
- `keras65_Reshape1`에서는 `y_test = ohe.fit_transform(y_test)` — test에도 **fit을 다시** 함. mnist는 test에도 0~9가 다 있어 결과는 같지만, 원칙은 **`ohe.transform(y_test)`**.

### 2-4. `np.tile`로 만든 이미지가 깨지는 이유 (`keras/keras50_flow2_next.py`)
```python
np.tile(x_train[0], 100)                         # (28, 2800)  ← 마지막 축(가로)으로 100번 이어붙임
np.tile(x_train[0], 100).reshape(-1,28,28,1)     # (100,28,28,1) 이지만 그림이 깨짐
np.tile(x_train[0].reshape(28*28), 100).reshape(-1,28,28,1)   # ✅ 정상: 784짜리 한 줄을 100번 → 100장
```
- 2D 배열을 그대로 tile하면 메모리 순서가 "**0행을 100번 → 1행을 100번 → …**". 이걸 28×28로 자르면 첫 장은 **원본 0행이 28번 반복된 줄무늬**가 됩니다.
- 그래서 먼저 `reshape(784)`로 **한 장을 한 줄로 펴고** tile해야 "같은 그림 100장"이 됩니다. (reshape 조건: 내용·순서가 그대로여야 함!)
- `datagen.flow(x, y, batch_size=100, shuffle=False).next()` → **튜플 (x배치, y배치)** → `xy_data[0].shape = (100,28,28,1)`, `xy_data[1].shape = (100,)`. 튜플이라 `.shape` 없음.
- `keras50_flow1`: 이미지 한 장 `(200,200,3)` → `np.expand_dims(arr, axis=0)` → `(1,200,200,3)` (모델·flow는 **배치 축**이 필요).
- 파이썬 3.11+에선 `it.next()` 대신 `next(it)`.

### 2-5. `return_sequences` 3단 LSTM + `validation_split`의 함정 (`keras/keras57_01_return_sequence.py`)
| 층 | 출력 shape | 파라미터 (`4×[units×(입력+units)+units]`) |
|---|---|---|
| `LSTM(10, return_sequences=True)` 입력 (3,1) | (None, **3**, 10) | 4×(10×11+10) = **480** |
| `LSTM(5, return_sequences=True)` | (None, 3, 5) | 4×(5×15+5) = **320** |
| `LSTM(5)` | (None, 5) | 4×(5×10+5) = **220** |
| `Dense(8)` / `Dense(1)` | (None,8) / (None,1) | 48 / 9 → **총 1,077** |
- `return_sequences=True` → 모든 timestep 출력(3차원 유지) → 다음 RNN에 연결 가능. 마지막 RNN은 False(기본) → 2차원 → Dense.
- **핵심 함정:** `validation_split=0.2`는 섞기 **전에 뒤쪽 20%** 를 떼어냅니다. 13개 × 0.8 → 앞 10개 학습, **뒤 3개 `[20,30,40],[30,40,50],[40,50,60]` 이 검증용**.
  → 모델은 1~13 범위만 학습하고 "10씩 뛰는 큰 숫자" 패턴은 한 번도 학습 못 함 → `[50,60,70]`의 예측이 **12.47**(정답 80)로 나온 주된 이유.
  → 고침: `train_test_split(shuffle=True)`로 미리 섞거나, 학습에 큰 값 샘플이 들어가도록 구성.

### 2-6. `Bidirectional` 파라미터 (`keras/keras59_Bidirectional1.py`)
- `Bidirectional(SimpleRNN(10), input_shape=(3,1))` → 정방향·역방향 RNN **2개** → 출력을 이어붙여 **(None, 20)**.
- 파라미터 = 2 × `10×(1+10+1)` = **240**. 다음 `Dense(10)` = 20×10+10 = **210**.
- `Bidirectional`은 **래퍼(wrapper)** — 혼자서는 층이 아니고 RNN 계열을 감싸서 씀.

### 2-7. `Reshape` 모델의 summary 직접 계산 (`keras2/keras65_Reshape1.py`)
| 층 | 출력 shape | 파라미터 |
|---|---|---|
| `Dense(280, input_shape=(28,28))` | (None, 28, **280**) — Dense는 **마지막 축만** 바꿈 | 28×280+280 = **8,120** |
| `Reshape((28,28,10))` | (None,28,28,10) — 28×280 = 28×28×10 = 7,840 ✅ | 0 |
| `Conv2D(64,(3,3))` valid | (None,**26,26**,64) | 64×(3·3·10+1) = **5,824** |
| `Conv2D(32,(3,3), padding='same')` | (None,**26,26**,32) ← 주석의 `(24,24,32)`는 **틀림**(same이라 크기 유지) | 32×(3·3·64+1) = **18,464** |
| `GlobalAveragePooling2D()` | (None, 32) | 0 |
| `Dense(32)` → `Dropout` → `Dense(16)` → `Dense(10)` | | 1,056 / 0 / 528 / 170 |
- 총 **34,162**. 두 번째 Conv2D 앞 `input_shape=(28,28,10)`은 첫 층이 아니라 **무시됨**.

### 2-8. `cross_val_predict(model, x_test, y_test)`의 의미 (`ml/m03`, `ml/m05`)
- `cross_val_score(model, x_train, y_train, cv=kfold)` → train 안에서 5번 학습·검증 → **점수 5개**. (모델 객체 자체는 fit된 상태로 남지 않음)
- `cross_val_predict(model, x_test, y_test, cv=kfold)` → **test 데이터를 다시 5등분해서 test로 학습**하고 남은 조각을 예측 → "train으로 학습한 모델의 test 성능"이 **아님**.
- 정석: `model.fit(x_train, y_train)` → `model.predict(x_test)` → `accuracy_score`.
- `m05`: `all_estimators(type_filter='classifier')` → `(이름, 클래스)` 튜플 리스트. `model = model()`을 **try 안에서** 해야 필수 인자가 있는 모델(예: `VotingClassifier`)의 에러도 잡힘.
- `m01`: 트리 계열(DT/RF/GB/XGB)은 `feature_importances_` 제공(합 = 1). `model.score`는 분류 → acc, 회귀 → R².

### 2-10. LangGraph — 리듀서·메모리·병렬 (`lg02`, `lg08_Memory02`, `lg09_병렬실행_병합2_concat`)
- `add_messages(msg1, msg2)`: id가 다르면 **이어붙임**(2개), id가 같으면 **덮어씀**(1개 — 뒤의 `AIMessage('방가', id='3')`만 남음).
- `lg08`: `compile(checkpointer=InMemorySaver())` + `config={"configurable":{"thread_id":"user01"}}`
  → 같은 thread_id로 두 번 invoke하면 이전 대화가 State에 쌓여 "내 이름이 뭐라고 했지?"에 답할 수 있음.
  → thread_id를 바꾸면 **새 대화**(기억 X). `InMemorySaver`는 **RAM**에만 저장 → 프로그램 종료 시 사라짐.
  → `tools_condition`: 마지막 메시지에 `tool_calls`가 있으면 `"tools"`, 없으면 `END`. 그래서 `tools → chatbot` 엣지만 추가하면 루프가 완성.
- `lg09_2`: `START → search`, `START → analysis` 두 엣지 → **같은 단계(superstep)에서 병렬 실행** → 둘 다 끝난 뒤 `merge`.
  - 두 노드가 **서로 다른 키**(`search_result`, `analysis_result`)에 쓰므로 리듀서가 없어도 충돌 없음.
  - 만약 둘 다 리듀서 없는 **같은 키**에 쓰면 같은 단계 동시 업데이트 → `InvalidUpdateError`.
  - "두 노드가 모두 끝나야 merge"를 명시하려면 `builder.add_edge(["search", "analysis"], "merge")` 형태도 가능.

# ✅ 정답 및 해설

### A
**A1.** 에러는 안 남. `' min'`은 허용값(auto/min/max)이 아니라 **경고 후 `auto`로 대체**. auto는 `val_loss` → min으로 추측하므로 결과적으로 정상. `val_acc`라면 이름에 acc가 있어 auto → **max**로 동작(역시 정상). 문제는 auto가 추측 못 하는 커스텀 지표.

**A2.** `x_val = scaler.transform(x_val)`. 빠지면 val_loss가 **원본 스케일 데이터**로 계산되어 학습 상태를 제대로 반영 못 함 → ES가 너무 일찍/늦게 멈추고, MCP는 잘못된 기준의 "best"를 저장, `restore_best_weights`도 엉뚱한 가중치 복원.

**A3.** **데이터 누수(data leakage)**. test의 min/max가 스케일 기준에 포함되어 test 정보가 학습 단계로 새어 들어감 → 성능이 낙관적으로 측정됨.

**A4.** (a) `(4, 5)` — 0~4 다섯 열 (b) `(4, 3)` — 0,1,4 세 열 (c) `(4, 3)`.

**A5.** 1차원이라 **ValueError**("Expected 2D array") → `y.reshape(-1,1)` 필요. `sparse_output` 기본(True)이면 **희소행렬(scipy sparse matrix)** 로 반환 → `.toarray()` 또는 `sparse_output=False`.

**A6.** (a) `(28, 2800)` (b) `(78400,)` (c) `(100,28,28,1)`. (a)를 reshape하면 첫 이미지는 **원본 0행이 28번 반복된 가로 줄무늬**(원본 그림이 아님).

**A7.** `tuple`, `2`, `(100,28,28,1)`, `(100,)`.

**A8.** `[20,30,40]`, `[30,40,50]`, `[40,50,60]` (섞기 전 **뒤쪽 20%**, `int(13×0.8)=10` → 앞 10개 학습). 학습 데이터에는 1씩 증가하는 작은 수(1~13)만 있고 10씩 증가하는 큰 수 패턴은 없음 → `[50,60,70]`을 학습 범위 근처 값(12.47)으로 예측.

**A9.** `(None,3,10)` 480 / `(None,3,5)` 320 / `(None,5)` 220.

**A10.** `(None, 20)`, 240. Dense(10) = 20×10+10 = **210**.
